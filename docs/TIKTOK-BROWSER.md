# Фоновая публикация TikTok

`tiktok-browser` — отдельный процесс с headless Chromium и постоянным профилем.
Он использует сайт TikTok Studio, без TikTok Developers и без обычного браузера владельца.

## Подключение

В `.env` задайте случайный `TIKTOK_BROWSER_TOKEN` (32+ байта). Это внутренний токен
обработчика, а не пароль TikTok. В Docker сервис и сайт получают его из одного файла.

Запуск: `docker compose up -d --build gudini-site tiktok-browser`.
В настройках сайта нажмите «Подключить TikTok», выберите QR-код, войдите через
телефон и нажмите «Я вошёл — проверить подключение». Окно показывает браузер сервера;
личный браузер компьютера не используется. Через 15 минут бездействия окно закрывается.

Для локального запуска: `npx playwright install chromium`, `npm run dev` и
в отдельном процессе `node --env-file=.env --import tsx worker/tiktok.ts`.
`TIKTOK_TRANSPORT=browser`, `TIKTOK_BROWSER_URL=http://127.0.0.1:43128`.

## Публикация

На странице готового проекта кнопка «Опубликовать в фоне» ставит неизменяемую копию
видео, описания и обложки в очередь. Необязательное время вводится в часовом поясе
браузера владельца, хранится в UTC. Фоновая публикация рассчитана на видимость «Все».

Переключатель «Автоматически публиковать новые готовые ролики» в настройках начинает
следить за новыми результатами монтажа. При включении существующие готовые ролики
запоминаются и не отправляются. Выключение прекращает добавление новых задач;
уже созданные отменяются отдельно в очереди. Один аккаунт на серверную сессию.

Процесс сохраняет очередь в `data/tiktok-browser/state.json`, профиль в `profile/`,
снимки файлов задач в `jobs/`. Всё находится в игнорируемом каталоге `data/`.
Профиль и кадры окна входа содержат секреты: их нельзя публиковать или коммитить.
Обработчик доступен только по внутренней сети Docker с токеном; интерфейс использует
существующую авторизацию сайта. Наружу порт обработчика не публикуется.

При истечении входа задача ждёт повторной авторизации. Если нажатие «Post» уже могло
дойти до TikTok, статус становится «Нужно проверить результат», без автоповтора.
После проверки в TikTok Studio владелец отмечает результат в настройках.
Один и тот же видеофайл в одном аккаунте повторно не отправляется, даже с другой подписью.

## Ограничения и проверка

TikTok может менять интерфейс, требовать проверку или отклонять серверные сессии.
Обработчик останавливается при неподдерживаемом редакторе, не отправляет молча видео
без выбранной обложки/описания. При отсутствии загрузки своей обложки публикация
также останавливается. Неподтверждённый результат не считается успехом.

Проверка без внешних публикаций: `npm run test:tiktok`, `npm run typecheck`.
Проверка браузерного редактора на локальной HTML-фикстуре (нужен Chromium):
`npx tsx --test tests/tiktokBrowserEditor.test.ts`. Она не обращается к аккаунту TikTok.
Живая проверка загрузки, обложки и финальной публикации требует подключённого аккаунта;
доступность страницы входа сама по себе её не заменяет.
