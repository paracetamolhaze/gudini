# Gudini — как устроен проект и почему именно так

Документ для тех, кто продолжит работу: человека или другой модели. Здесь не
только «что где лежит», но и **почему** каждое решение принято. Почти каждое
правило в этом коде появилось после конкретной поломки, и без этой истории его
легко откатить обратно.

---

## Что делает продукт

Веб-студия коротких вертикальных роликов для стримеров. Путь:

```
тема или ссылка
  → исследование истории (проверенные факты с источниками)
  → сценарий
  → запись с телесуфлёра
  → расшифровка речи, чистка запинок
  → медиатека реальных материалов события
  → монтажный план
  → рендер 9:16 с субтитрами по одному слову
  → обложка
  → публикация в TikTok / YouTube / Instagram
```

Стек: Next.js 15 (App Router) + TypeScript, хранилище — файлы JSON (`data/db.json`),
сайт на Railway, тяжёлый воркер — Docker на машине владельца, монтаж — FFmpeg.

---

## Тип истории: конвейер готов к любой теме

Конвейер писался под новости: событие, участники, год, репортажи. На теме про
кино («Мстители: Судный день») это давало пустую медиатеку: постеры отсекались как
«заставка», кадры из фильма — как «постановка», фан-сайты — за «сущность не
упомянута». Исследование теперь определяет **тип истории** (`research.kind`:
NEWS_EVENT, ENTERTAINMENT, EXPLAINER, PERSON, PRODUCT, HISTORY, OTHER) и пишет
**памятку по визуалу** (`visualGuide`, англ.): какие кадры и источники уместны.
По типу меняются: проверка источника (вне новостей — «относится к теме», без года и
турнира), QC кадров (`staged`: постеры и снятые сцены допустимы; призывы канала,
интерфейс, скриншоты — мусор при любом типе), формулировка потребностей блоков
(«official still of Doctor Doom», IMAGE вместо VIDEO), запросы (от названия темы).
Тип входит в отпечатки блоков и медиатеки: пакет, собранный «как для новостей»,
пересобирается. У старых пакетов тип отсутствует и считается NEWS_EVENT.

## Главный принцип: сначала факты, потом картинка

Ролик рассказывает о реальном событии. Значит, ни одна стадия не имеет права
выдумывать: сценарий пишется только по найденным фактам, перебивки берутся только
из проверенного материала этой истории, а не «похожего по теме».

Из этого следует всё остальное:

- **Никаких тихих подмен.** Если стадия не отработала, задача останавливается.
  Молчаливый возврат пустоты однажды уничтожил девять готовых видео-сегментов и
  выдал «0 материалов» вместо ошибки.
- **Никаких автоматических фолбэков между провайдерами.** Провайдер, оказавшийся
  доступным, не становится подходящим.
- **Проверяем результат, а не намерение.** План может быть безупречным, а в файле
  вставки не окажется.

## Порядок стадий (Montage V3)

```
Project
 └─ StoryResearchPack        факты, участники, дата, источники
     └─ Script                пишется ТОЛЬКО по фактам пакета
         └─ ScriptBeats       разбор сценария на визуальные блоки 2–6 с
             └─ StoryAssetPack медиатека под эти блоки
                 └─ recording → ASR → Speech Cleanup → фиксация таймкодов
                     └─ Creative Director   расстановка по дословным цитатам
                         └─ MontageValidator
                             └─ FFmpeg render
                                 └─ RenderConformanceCheck  (бесплатно)
                                     └─ RenderCritic        (1 платный вызов)
```

Точка входа в production: `lib/pipeline.ts` → `runMontageV3()` из
`lib/montageV3Pipeline.ts`. Старые планировщики (`editPlanner`, `editPlannerPack`,
`broll`) **удалены из production-пути** и недостижимы по графу импортов.
`MONTAGE_V3=false` бросает ошибку, а не включает старую систему: иначе однажды
выйдет ролик, собранный не той системой, и понять это по результату будет нельзя.

## Политика провайдеров — жёсткая

```
Anthropic   весь текст, рассуждение и зрение:
            Story Research, Script, Script Beats, Media Research reasoning,
            Source/Visual Verification, Beat Matching, Speech Cleanup,
            Creative Director, Metadata, Cover Concept, Cover QC
Brave       только поиск: news / videos / images / web
OpenRouter  РОВНО одна стадия: генерация картинки обложки
            (google/gemini-3.1-flash-image)
ASR         только расшифровка речи
yt-dlp      скачивание публичных видео, $0
FFmpeg      вся локальная обработка и рендер, $0
```

`lib/providerPolicy.ts` — таблица `stage → allowed providers`. `assertProvider()`
вызывается **до** сетевого запроса (`lib/mediaLlm.ts`, `lib/braveSearch.ts`,
`lib/brollWeb.ts`, `lib/coverProvider.ts`). `lib/costLedger.ts` проверяет ещё раз
при записи расхода — второй уровень, не первый.

**Почему так строго.** Подмена провайдера на ходу молча меняет качество разбора
и цену ролика, а понять постфактум, чем собран конкретный ролик, уже невозможно.
Поэтому недоступность своего провайдера — остановка задачи, а не переход к чужому.
Из `brollWeb.ts` по этой же причине удалён запасной переход на Serper.

Аудит: `npx tsx _policy-audit.ts` — обходит импорты от реальных точек входа
(HTTP-маршруты + воркер) и проверяет достижимость, а не наличие строк в файлах.

## Деньги

`lib/costLedger.ts` записывает каждый платный вызов: провайдер, модель, стадия,
токены, кэш, `providerReportedCost`, `estimatedCost`, флаги `failed` / `retry`.
Названная провайдером сумма имеет приоритет над тарифом.

- Неудачные и повторные вызовы **входят** в стоимость: иначе цифра занижена.
- Brave тарифицируется за запросы, а не за найденные результаты.
- `assertBudget(stage, projectedCost)` останавливает трату **до** отправки:
  проверяется не только потраченное, но и оценка самого запроса (по длине
  промпта, числу кадров и `max_tokens`, намеренно пессимистично).
- Стадия, которая не запускалась, помечается `NOT RUN`, а не `$0`.
  Уже оплаченная ранее — `HISTORICAL`. Невосстановимая — `UNKNOWN`.

Отчёт: `lib/costReport.ts` — `CURRENT RUN COST`, `FULL VIDEO VARIABLE COST`
(`INCOMPLETE`, пока есть `NOT RUN`), `PROVIDER USAGE`, инфраструктура отдельно.

Переменные: `MEDIA_JOB_WARN_COST_USD`, `MEDIA_JOB_MAX_COST_USD`,
`MEDIA_JOB_HARD_LIMIT=1`, `INFRA_MONTHLY_USD`, `INFRA_VIDEOS_PER_MONTH`.

## Переиспользование: за одно и то же не платим дважды

- **ScriptBeats** сохраняются в `script-beats.json` с отпечатком от сценария,
  истории и версии разбора.
- **StoryAssetPack** сохраняется с `fingerprint` от истории, фактов, участников,
  блоков, плана медиа-исследования, `PACK_VERSION` и `QC_RULES_VERSION`.

Профиль монтажа (`montage-taste.json`: темп, длительности) в отпечаток **не**
входит: он влияет на то, как материал расставлен, а не годится ли он. Смена темпа
не должна заново оплачивать поиск и зрение.

Повторный рендер того же ролика: `packReused = true`, поиск и зрение = $0.

## Retrieval: как находится материал

`lib/storyAssetPack.ts`, два слоя:

- **CORE** — один глубокий заход за главным видео события. Кандидаты со всех
  запросов собираются, ранжируются **по метаданным** (`scoreCandidate`: участники,
  слова канонического события, год, канал), и качается только верх списка.
  Порядок выдачи Brave к сюжету отношения не имеет.
- **BEAT** — точечный добор под незакрытые блоки. Видео ищется раньше картинок.

Проверка источника (`verifySource` в `lib/storyAssets.ts`): нужна хотя бы одна
сущность истории; другой год — отказ; **другое соревнование при том же герое —
отказ**. Последнее добавлено после того, как в пакет попало фото «Henderson …
during Ajax Europa League match»: имя совпало, года в тексте не было.

### YouTube — подтверждённый рабочий набор, не менять

```
--js-runtimes node    yt-dlp по умолчанию включает только deno
bv*[height<=1080]     YouTube отдаёт видео и аудио раздельно; звук нам не нужен
```

Потолок 1080p с защитой по размеру: 1080p берётся, только если yt-dlp знает размер
и он меньше 200 МБ; иначе 720p, как раньше. Лимит файла 220 МБ, таймаут 6 минут. Ошибки yt-dlp логируются **дословно**:
ранее стоявшая подстановка «поток недоступен без входа/подписи» превращала обычный
промах с форматом в мнимую защиту площадки и стоила нескольких дней.

Обходов защиты нет и не будет: DRM, paywall, логин, CAPTCHA, приватный контент,
чужие cookies. Не скачивается штатно — источник пропускается.

## Скорость медиатеки: окна вместо файлов, три видео разом, исследование параллельно

Медиатека для двухминутного ролика собиралась 10–15 минут: десять видео строго по
очереди, каждое качалось целиком в 1080p ради нескольких трёхсекундных окон, а
процессор простаивал, пока ждали сеть. Три изменения, результат не меняющие:

- **Скачиваются только окна** (`fetchVideoSections`): yt-dlp `--download-sections`
  с `--force-keyframes-at-cuts` отдаёт куски по 3.5 с ровно с начала окна; кадр
  берётся по локальному времени куска. Окна считаются той же формулой
  (`planWindows`), что и раньше, поэтому индексы кэша зрения не сдвигаются. Если
  куски не отдались — файл качается целиком, как прежде.
- **Три видео одновременно** (`PARALLEL = 3`) и в основном шорт-листе, и в доборе
  под блоки; результаты применяются в порядке шорт-листа, чтобы состав медиатеки не
  зависел от того, чья загрузка закончилась раньше. Одно видео два блока не
  скачают: пометка в `seenVideo` ставится синхронно до первого `await`.
- **Исследование истории** запускается в начале задачи параллельно с распознаванием,
  чисткой речи и перекодированием; результат нужен только к сборке медиатеки.

## Контроль качества материала

`lib/brollRelevance.ts` — пакетный разбор кадров одного исходника **одним**
запросом. Признаки мусора: `hasLargeText`, `hasChannelPromo`, `hasFaceOverlay`,
`isTitleOrOutroCard`, `hasPlayerOrSocialUi`, `isStudioExplainer`,
`isReenactmentOrSkit`, плюс `sceneFamily` (смысловая сцена: CELEBRATION,
STRETCHER, PRESS_CONFERENCE…). Гейт `qcReject()` один и применяется одинаково к
кадрам видео и к фото.

### SegmentWindowQC — решение по всему окну

`segmentWindowDecision()` в `lib/storyAssetPack.ts`. Проверяются **пять точек**
реально вырезаемого окна (0.05 / 0.25 / 0.5 / 0.75 / 0.95):

- грязь у конца → окно подрезается до чистой границы (`TRIM`);
- грязь у начала или чистого меньше 1.5 с → сегмент не берётся (`REJECT`);
- исход есть у каждой точки, пропусков нет.

**Почему.** Раньше зрение смотрело один «представительный» кадр, а резались 3.2
секунды вокруг него. В готовый ролик так попала чужая карточка
«THANKS FOR WATCHING» с кнопкой SUBSCRIBE: кадры на 0.16 и 0.80 с были чистыми,
а с 1.60 с шла заставка.

Кадры для QC уменьшаются до 384 px (`QC_FRAME_WIDTH`) и разбираются младшей
моделью (`WINDOW_QC_MODEL`, переопределяется `MEDIA_WINDOW_QC_MODEL`). На том же
регрессионном случае младшая модель дала идентичный ответ втрое дешевле.

## Сопоставление с блоками

Матрица «блок × материал» за один вызов, оценки:

```
3  на кадре именно то, о чём блок
2  хорошо иллюстрирует смысл
1  годится как обстановка
0  не подходит
```

Идентификаторы блоков собирает уже детерминированный код. Материал может
подходить нескольким блокам и не закрепляется за одним.

**Покрытие считается двумя числами:** `hardCoverageRatio` (оценка ≥ 2) и
`coverageRatio` (≥ 1). Готовность определяется **жёстким**: пакет с жёстким
покрытием 31% выглядел готовым и дал двадцать четыре секунды одного лица.

## Разнообразие кадров

- `lib/sceneHash.ts` — перцептивный dHash, группировка почти одинаковых планов
  (расстояние Хэмминга ≤ 12 из 64). Считается локально, денег не стоит.
- `sceneFamily` из разбора кадра — смысловая сцена. Хэш различает ракурсы, но не
  понимает, что пять планов у рекламного щита это одно место.
- Режиссёр не ставит подряд два кадра одной сцены и не берёт оценку 1, когда под
  блок есть оценка 3.

## Чистка речи: паузы по зазорам слов, вырезка забирает хвосты

Расшифровка — ElevenLabs Scribe (пословные таймкоды), Whisper только запасной.
Пословная расшифровка сохраняется в `transcript.json`, стоимость ASR — в леджер.

Что было не так на проекте Хендерсона (паузы на 0:15, 0:30, 0:34 в готовом ролике):

| Симптом | Причина | Исправление |
|---|---|---|
| вдох 0.77 с между предложениями остался | детектор тишины −40 дБ / ≥0.6 с не видел вдох; валидатор не трогал паузы <0.8 с | детектор −34 дБ / 0.3 с; паузы = тишина ∪ зазоры между словами ≥0.5 с (`pausesFromWords`); удержание 0.35 с; неклассифицированные >1.2 с ужимаются |
| после вырезанного фальстарта «…эк-- э-э-э,» пауза 0.56 с | вырезка кончалась на последнем слове фрагмента | вырезка забирает зазоры вокруг, оставляя ≤0.12 с с каждой стороны |
| «щит и … и спотыкается» | союз перед фальстартом не входил в вырезку; второй проход шёл без пауз | промпт: союз перед фальстартом — часть фальстарта; второй проход получает паузы на чистом таймлайне, `cleanToRaw` переводит их в сырое время |
| обрывы «под--», «э-э-э» зависели от модели | — | `deterministicFillers`: режутся без модели, уверенность 0.95 |

Один путь для конвейера и для перечистки готового проекта: `speechCleanupRun.planCleanupCuts`.
Перечистка готового проекта: `_cleanup2.ts` — сохранённая расшифровка → план → новый
`clean.mp4`, слова на новом таймлайне в `words.clean.json`, план режиссёра переводится
на новый таймлайн через исходное время (без второго вызова режиссёра).

## Сборка по сценарию: из нескольких дублей остаётся лучший

Автор читает с телесуфлёра и перечитывает абзацы: запись 3:41 при сценарии на
полторы минуты речи. Модель находит дубли, но режет не больше 15 с за проход —
для многократных перечитываний этого мало. `lib/takeSelection.ts` делает это без
модели: сценарий режется на предложения; для каждого в расшифровке собираются все
попытки (от слова, похожего на одно из двух первых значимых слов предложения,
вперёд по порядку слов, с допуском до трёх чужих слов подряд; повтор первого слова
— новая попытка; короткий обрыв после последнего совпавшего слова — хвост попытки).
Попытка засчитывается от 3 совпавших слов и 30% предложения, полное прочтение — от 60%.
Остаётся лучшая (полнота, без обрывов; при равных — последняя), порядок предложений
сохраняется. Остальные попытки вырезаются целиком, без предела на длину: полные —
всегда, неполные — только рядом с оставленной. Если оставленная попытка не дочитана
или с обрывом, а дальше автор дочитывал хвост («…сражаться-- которым придётся
сражаться с лицом человека…»), берётся последнее дочитывание: голова из оставленной,
хвост из него, всё между уходит. Речь, не совпавшая ни с одним предложением:
повтор фразы — остаётся последнее произнесение; слова монтажёру («заново», «сорри,
нарежешь») и болтовня рядом с неудачной попыткой — уходят; импровизация для зрителя
(«с болельщиками», «если честно, у меня мурашки») остаётся. Проверено на двух
реальных записях: Хендерсон (1:18, три дубля) и «Мстители» (3:41, 25 предложений,
из 221 с уходит ~80 с ещё до модели).

В общем пути чистки (`speechCleanupRun.planCleanupCuts`) это шаг 0; затем обрывы
без модели; затем два прохода модели уже на сокращённой расшифровке (паузы и
индексы переводятся между чистым и сырым временем). Регрессия — на реальной
расшифровке Хендерсона (`tests/fixtures/henderson-takes.json`): три известных дубля.

Субтитры по умолчанию снова по одному слову, стиль первых роликов (Arial 84,
белый, обводка 6, поле 560) — по просьбе автора; фразовый режим доступен через
`captionStyle.mode: "phrase"`.

## Субтитры: фразы по смыслу, а не по счётчику слов

Распознавание отдаёт слова без знаков, и фразы резались механически:
«ПОЛУЧИТЬ ЖЁЛТУЮ КАРТОЧКУ ЧЕМПИОНАТ МИРА 1/8». Границы теперь берутся из сценария
(`lib/scriptPunctuation.ts`): произнесённые слова выравниваются с текстом по
буквенному скелету (с терпимостью к окончаниям — «Мексикой»/«Мексики»), и каждому
слову достаются знак, конец предложения/абзаца и признак ключевого слова (число,
имя не в начале предложения). Если речь начала новое предложение сценария, а
предыдущих слов в тексте не было («…опытный футболист. Весь матч…»), граница всё
равно ставится.

Группировка (`lib/subtitles.ts`): речь режется на клаузы — конец предложения,
абзаца и пауза ≥0.42 с — жёстко, запятая/двоеточие/тире — мягко. Короткие клаузы
внутри предложения склеиваются до maxWords (6), длинные делятся на почти равные
части так, чтобы часть не обрывалась на предлоге, союзе или «не»/«ни». Сирота из
одного слова уходит к предыдущей фразе. На экране преимущественно две
сбалансированные строки (≤20 знаков), знаки препинания показываются (кроме
запятой в конце фразы), ключевые слова крупнее на 8 pt — размером, не цветом.
Слова, которых не было в речи, не добавляются.

## Медиатека: стоп-кадр под смысл и раскадровка до оплаты

Стоп-кадр окна выбирается не «первый чистый», а по совпадению описания кадра с
потребностями блоков (`pickFrameForNeeds`), из тех же описаний, что дал
SegmentWindowQC — зрение не вызывается второй раз. Кэш зрения ключуется по индексу
кадра (`seg:{video}:{i}`), поэтому число окон при перерезке должно совпасть с
прошлым прогоном — `_recut.ts` берёт его из самого кэша.

Перед оплатой режиссёра строится раскадровка (`_storyboard.ts`): блок + три лучших
кандидата по оценке сопоставления. Её смотрит человек. Так были сняты торс без
головы в форме 2012 года с оценкой 3 для четырёх блоков, кадр с декоративной
рамкой (теперь отказ QC по описанию) и три кадра чужих матчей. Обрезка карточки
смещена к верху (`CARD_FILTER`, 15% лишней высоты сверху) — у портретных фото
лицо в верхней трети.

## Уплотнение плана по блокам (`_refine.ts`, $0)

Режиссёр на этом проекте отдал 10 карточек на 57 секунд: две по 6.3 с подряд и
одна на 16.6 с — технически валидно, но не публикуемо. Вместо второго платного
вызова план перестраивается детерминированно от блоков сценария:

- отрезок каждого блока — по времени его слов в речи (выравнивание по двум первым
  значимым словам ≥4 букв с терпимостью к окончаниям; «так», «его» не в счёт);
- выбор режиссёра закрепляется за тем из перекрытых им блоков, где у кадра выше
  оценка (гипс — на «рука в гипсе», медики — на «носилках»); правила проекта
  соблюдаются: материал используется один раз, у вставки есть цитата речи;
- блоки с самым коротким списком сильных кандидатов получают материал первыми —
  иначе портреты героя уходят в начало, а концовке нечего показывать;
- отрезок длиннее max_visual_duration делится по границам фраз субтитров; части
  заполняются своими кандидатами, запасной пул контекста — только для отрезков
  длиннее 8 с (на коротком лучше одна карточка чуть длиннее нормы, чем чужой по
  тону кадр);
- порядок частей внутри отрезка — по совпадению сказанных слов с описанием кадра
  (маленький словарь: гипс↔cast, носилки↔stretcher, судья↔referee, скамейка↔bench…).

Результат на проекте Хендерсона: 15 карточек по 2.5–5.4 с, все 12 блоков на своих
местах, сверка 45/45. Логика живёт в `lib/montageRefine.ts` и вызывается в
`runMontageV3` сразу после режиссёра — следующие ролики получают этот темп
автоматически; `_refine.ts` — обёртка для перерендера готового проекта.

## Три слоя проверки результата

Каждый появился после реальной поломки — и ловит разное.

### 1. Валидатор плана (`lib/montageValidator.ts`) — бесплатно

Ошибки, а не замечания: покрытие ниже 50%, непрерывный A-roll больше 8 с, первая
вставка позже 5 с, все вставки в отрезке короче половины ролика, материал не из
пакета, дубли, пересечения, отсутствие дословной цитаты.

`montagePreflight()` считает **распределение**: `firstExternalVisualAt`,
`maxContinuousARoll`, покрытие по третям. При нехватке — статус
`NEEDS_MORE_MEDIA`, и режиссёр **не оплачивается**: он выбирает из имеющегося и
материал не создаёт.

### 2. RenderConformanceCheck (`lib/renderConformance.ts`) — бесплатно

Сверяет **готовый файл** с планом по перцептивному хэшу: три точки на вставку,
исход `PASS` / `FAIL` / `ERROR` у каждой. Недобор точек сам по себе провал.

Для изображения эталон — сама картинка (у неё нет кадра «в момент 0.3 с»), для
видео — кадр на соответствующем смещении. Оба приводятся к монтажному виду
1080×1920.

### 3. RenderCritic (`lib/renderCritic.ts`) — один платный вызов

Готовый ролик раскладывается в подписанную таймкодами раскадровку и показывается
модели целиком. Ищет то, что не видно из плана: длинные провалы, скученность
вставок, чужие заставки, повторы сцен, несоответствие речи. Ответ — `pass`,
`score`, список проблем с таймкодами. Автоматических платных пересборок нет:
критик сообщает, решение принимает человек.

## История поломок: что сломалось, почему и чем закрыто

Читать перед тем, как «упростить» любую из проверок.

| Поломка | Корневая причина | Что теперь защищает |
|---|---|---|
| «0 материалов» при девяти готовых сегментах | ошибка сопоставления проглочена `try/catch`, фильтр обнулил пакет | обязательные стадии бросают; пустой пакет при наличии материала — ошибка |
| YouTube: 45 находок → 0 скачиваний | yt-dlp включает только deno; селектор требовал единый файл с аудио | `--js-runtimes node`, `bv*`; ошибки логируются дословно |
| «Поток недоступен без входа/подписи» | наша же подстановка поверх настоящей ошибки формата | подстановка удалена и в скачивании, и в probe |
| Фото Ajax из другого турнира | проверялись сущность и год, но не соревнование | `conflictingCompetition()` |
| SUBSCRIBE внутри проверенного сегмента | QC смотрел один кадр, резались 3.2 с | `segmentWindowDecision()` по пяти точкам окна |
| Фото пропало из MP4 | JPEG — один кадр; без `-loop 1` overlay сразу пропускал A-roll | картинки подаются с `-loop 1 -t`; кадровый регресс-тест |
| Сверка «не заметила» пропажу | `continue` при неудачном съёме кадра, 21 точка из 24 | исход у каждой точки, недобор = провал |
| 24 секунды одного лица | темп был предупреждением | темп — ошибка; `montagePreflight` до оплаты режиссёра |
| Цвет A-roll «прыгал» | punch-in делал вторую ветку масштабирования | punch-in удалён; A-roll ровно один путь `scale→crop→fps` |
| Обложка не проходила QC из-за кикера | кикер попадал в проверку заголовка | кикер вырезается перед сверкой |
| Дубли материалов при параллельном подборе | резервирование после `await` | синхронная пометка до любого `await` |

## Запуск целиком на своём компьютере (Docker)

Railway с томом 500 МБ не вмещает исходник на гигабайт; переезд сайта в Docker
рядом с воркером снимает лимит — диск свой. `docker-compose.yml` поднимает:

| Сервис | Что | Данные |
|---|---|---|
| `gudini-site` | сайт (Next.js), `http://localhost:3000` только с этого компьютера | том `gudini-site-data` (`/app/data`: проекты, загрузки, ролики) |
| `gudini-worker` | монтаж; ходит на сайт по внутренней сети `http://gudini-site:3000` | том `gudini-worker-data` |
| `caddy` (профиль `public`) | HTTPS для домена DuckDNS, сертификат Let's Encrypt через DNS-запись | `caddy-data` |
| `duckdns` (профиль `public`) | обновляет IP домена при смене адреса провайдером | — |

Публичный HTTPS нужен камере в браузере телефона, OAuth-коллбэкам TikTok/YouTube/Meta
и Instagram Reels (скачивает ролик по ссылке). Для него: в `.env` — `DOMAIN`,
`DUCKDNS_SUBDOMAIN`, `DUCKDNS_TOKEN`, `SITE_URL=https://…duckdns.org`; на роутере —
проброс порта 443 (и 80) на этот компьютер; провайдер должен давать публичный IP
(за CGNAT проброс не работает — тогда Tailscale Funnel). После смены адреса — новые
Redirect URI в консолях TikTok, Google, Meta и повторное подключение аккаунтов.

Перенос с Railway: список проектов экспортируется через `GET /api/projects` в
`db.json`, файлы готовых проектов уже лежат в томе воркера; ключи — из `.env`.

```bash
docker compose up -d --build                    # сайт + воркер
docker compose --profile public up -d --build   # + HTTPS, когда домен готов
```

## Аудит 2026-09-05: блок «сразу» (без изменения стоимости ролика)

Отчёт: `docs/PROJECT-AUDIT-2026-09-05.md`. Из него сделан блок правок, которые не
трогают ни один платный вызов; цена ролика прежняя. Что и почему:

- **Удаление проекта** (`lib/store.ts`): id проверяется по формату `[a-z0-9_-]{1,64}`,
  папка удаляется только у существующего проекта и только внутри `data/uploads`.
  Раньше `rmSync` получал любой id без проверки — на открытом сайте это снос данных.
  `projectDir()` с недопустимым id бросает ошибку.
- **Исходник закрыт** (`middleware.ts`): без пароля открыты только готовый ролик и
  обложка (их тянут Instagram/TikTok), `?which=raw` требует входа.
- **db.json не теряется**: запись атомарная (tmp + rename), прежняя версия остаётся в
  `db.json.bak`. Битый файл больше не читается как пустой: восстанавливается из
  резервной копии (битая копия остаётся в `db.json.corrupt`), а без неё чтение
  бросает ошибку и запись запрещена.
- **Пульс воркера на всю задачу** (`worker/index.ts`): сигнал на `/api/worker/progress`
  идёт каждые 2 с от скачивания исходника до отправки результата. Раньше на долгом
  скачивании сайт считал воркер выключенным (90 с тишины) и запускал монтаж у себя —
  второй конвейер и двойная оплата. В докер-сборке серверный монтаж отключён совсем:
  `WORKER_ONLY=1` у сайта, при молчащем воркере кнопка отвечает 503 с объяснением.
- **Сверка готового файла с планом** (`lib/pipeline.ts` → `checkRenderConformance`):
  после selfCheck в продакшене проверяется, что в области карточки запланированная
  картинка, автор не перекрыт, карточка неподвижна. Результат в `conformance.json`.
  Ошибки проверки или провалов больше max(2, 15 % точек) — ошибка стадии. Локально,
  ffmpeg, 30–60 с на двухминутный ролик. `RENDER_CONFORMANCE=off` отключает.
- **Ключи кэша по содержимому** (`lib/fileFingerprint.ts`): расшифровка и план чистки
  привязаны к отпечатку файла (размер + sha1 первых и последних 4 МБ) и хэшу текста
  сценария, а не к длине; старые ключи принимаются, уже оплаченное не пересчитывается.
  Воркер сверяет локальный исходник с сайтом по `ETag` (тот же отпечаток), а не по
  одному размеру.
- **Паузы одной формулой** (`pauseCut` в `lib/speechCleanupPlan.ts`): первый прогон,
  механический фолбэк и восстановление плана из файла режут паузу одинаково.
- **Слова-маркеры болтовни** (`lib/takeSelection.ts`): слова монтажёру («заново»,
  «нарежь», «перепиши») режут кусок любой длины; обычные слова («стоп», «сначала»,
  «ладно», «ок») — только короткий кусок (≤5 слов или ≤3 с). Фраза из сценария,
  начинающаяся с такого слова, и так была защищена; теперь защищена и длинная
  импровизация с «ок» внутри.
- **Распознавание речи не подменяется молча**: если Scribe и Whisper недоступны,
  стадия падает с их ошибками (одна повторная попытка Scribe только на сетевой сбой).
  Субтитры по сценарию «на глаз» включаются явно: `SUBTITLES_FROM_SCRIPT=1`.
- **Мелочи интерфейса**: имя файла в заголовке загрузки кодируется (кириллица роняла
  fetch); ошибка API больше не записывается в проект как проект; неудачная
  перегенерация обложки возвращает прежнюю (файл откладывается в `cover-prev.jpg`
  на время попытки) и отвечает 409 с объяснением.

Не делалось (по решению после разбора): резервирование бюджета для параллельных
запросов, версии заданий, OAuth state и семантика «опубликовано» — до реальной
публикации из Gudini; платный критик рендера — не включён.

## Балансы API (страница /balances)

`lib/balances.ts` + `GET /api/balances` (кэш 10 минут, `?refresh=1` обновляет) —

Нужен ключ со страницы Console → Settings → Admin keys (`sk-ant-admin01-…`) или Personal без привязки к workspace; ключ workspace даёт 401, ключ без прав — 403; строка называет, что исправить (Scope без workspace, право «Workspace Analytics: Access») |
| OpenRouter | остаток лимита ключа, расход за месяц | `/api/v1/key` (`limit`, `limit_remaining`, `usage_monthly`); остаток кредитов аккаунта отдаёт только management-ключ |
| ElevenLabs | кредиты тарифа, дата сброса | `/v1/user/subscription`; ключу нужно право User: Read, иначе строка объясняет, что включить |
| Brave | ничего по API: остаток и расход Brave не отдаёт, квоты нет (оплата по факту, $0.005 за запрос), а любая проверка ключа — платный запрос; остаток считается по журналу от введённого месячного кредита | без сетевых запросов |

OpenAI (Whisper) на дашборде не показывается: ключа нет, это запасной путь расшифровки.

### Журнал расходов и остаток «по нашему учёту»

Anthropic и Brave остаток по API не отдают, поэтому он считается у нас (`lib/spendLog.ts`):

- **Источник.** Каждый прогон конвейера заканчивается файлом `cost-runs/<метка>-<статус>.json`
  (копия pipeline-cost.json со всеми записями леджера). Воркер после каждой задачи и при старте
  шлёт сводки всех таких файлов на `POST /api/worker/spend` — сумма и разбивка по провайдерам,
  runId = `<projectId>:<файл>`, повтор безопасен. Платные действия сайта (сценарий, описание,
  исследование, ручная обложка) записываются через `recordSiteSpend` — по записям леджера,
  появившимся за время вызова. Журнал: `data/spend-log.json` на сайте.
- **Остаток.** Пользователь вводит число из консоли провайдера в строке дашборда («ввести
  остаток из консоли», `POST /api/balances/manual`, файл `data/balances-manual.json`). Момент
  ввода — точка отсчёта: остаток = введённое − расход по журналу после этого момента. После
  пополнения число вводится заново. Уровни: пусто ≤ 0, мало < 15 % введённого; абсолютного
  порога нет — $0.84 при введённых $0.84 это полный остаток, а не тревога.
- **На странице.** Под таблицей — журнал: последние 40 прогонов с датой, проектом, действием,
  статусом, суммой и разбивкой по провайдерам; в шапке журнала — расход за сегодня и за месяц.
  На главной провайдеры не опрашиваются: `GET /api/spend` отдаёт только журнал для «≈ $» у
  проекта. «Сегодня» и «месяц» считает браузер в часовом поясе пользователя. Арифметика —
  `lib/spendMath.ts`.
- **Точность.** Цены — тарифные либо названные провайдером (OpenRouter возвращает свою);
  прогоны до появления леджера (Хендерсон) и неудачный прогон 5 сентября в журнале отсутствуют.

Уровни строк: ok / low (<15 %) / empty / unknown (остаток API не отдаёт) / missing /
error. Пока сайт открыт без пароля, эндпоинт тоже открыт — секретов в нём нет.

## Claude через OpenRouter (транспорт конвейера)

`MEDIA_LLM_TRANSPORT=openrouter` + `OPENROUTER_CLAUDE_KEY` (ключ «gudini claude», отдельный от ключа
обложек) — все текстовые и зрительные вызовы конвейера идут к тем же моделям Claude через OpenRouter
(`lib/mediaLlm.ts`: `openrouterChat`, модели с префиксом `anthropic/`). Почему: тарифы на токены
одинаковые, но Anthropic начисляет 16 % налога на пополнение, OpenRouter — 5,5 % комиссии; вдобавок
OpenRouter возвращает точную цену каждого вызова (`usage.cost` → `providerReportedCost` в леджере), а
остаток лимита ключа виден на `/balances` без ручного ввода.

Правила не изменились: провайдер моделей в учёте и политике — `anthropic`; транспорт выбирается
только настройкой, автоматического перехода между прямым Anthropic и OpenRouter нет (нет ключа
выбранного транспорта — стадия падает). Обрезка ответа (`finish_reason=length`) — ошибка «обрезан по
лимиту» без повтора; 429/5xx — один повтор, как и раньше. Кэширование промптов конвейер не использует,
поэтому через OpenRouter ничего не теряется. Тесты изоляции разрешают адрес OpenRouter только
`mediaLlm.ts` (транспорт), `cover*` и `balances.ts`.

## Звук: шум и частота дискретизации

В финальном рендере голос идёт через `afftdn` (лёгкое подавление шума, nr=10) → `loudnorm` →
`aresample=48000`, и кодируется AAC 48 кГц (`-ar 48000`). Раньше `loudnorm` отдавал 192 кГц, ролик
кодировался в AAC 96 кГц — в слышимом диапазоне это давало шипение, а подъём громкости на 10–15 дБ
поднимал вместе с голосом шум комнаты. Проверено на Мстителях: шум в паузах ниже на 5 дБ при той же
громкости. Готовому ролику звук можно пересобрать без монтажа: `-c:v copy` с тем же фильтром.

## Кадр автора: одинаковое кадрирование в телесуфлёре, записи и монтаже

Телесуфлёр формирует кадр 1080×1920 в canvas: камера заполняет вертикальную область 9:16,
лишняя часть сенсора обрезается до записи и сразу видна пользователю как выбранные границы.
Превью и видеодорожка записи берутся из одного canvas; текст телесуфлёра остаётся отдельным
элементом интерфейса и в исходник не записывается. Превью и запись одинаково ориентированы,
без отдельного зеркального отражения только на экране. Формат сенсора камеры сам по себе
не гарантирует формат записи: важен уже сформированный кадр canvas.

`authorFitFilter(displayWidth, displayHeight)` в `lib/pipeline.ts` сохраняет эту геометрию при
чистке и финальном рендере: исходник 9:16 только приводится к 1080×1920. Автоматический
вступительный зум удалён — после начала монтажа границы кадра больше не сдвигаются. Равенство
кадрирования не означает побитовое равенство: видео перекодируется, а монтаж добавляет карточки
и субтитры поверх записанного изображения.

Отдельно загруженные файлы другого формата по-прежнему вписываются целиком, поля заполняются
размытой копией кадра; скрытого центрального crop для них нет. `probe()` отдаёт
`displayWidth/Height` с учётом метаданных поворота: телефоны могут писать 1920×1080 + rotate=90.
Регрессия в `tests/renderIntegrity.test.ts` проверяет настоящие рендеры четырьмя цветными
маркерами у краёв кадра, в начале и после 1,5 с, для исходника напрямую и после чистки речи.

После остановки записи телесуфлёр воспроизводит сохранённый файл: его можно использовать или
перезаписать. Камера и микрофон на время просмотра освобождаются. Уход со страницы и отключение
дорожки останавливают запись для проверки, вместо продолжения с неподвижным изображением.

`npm run test:capture` запускает браузерные проверки с синтетической камерой и звуком, без
доступа к реальным устройствам и API. Нужны FFmpeg/ffprobe и Chromium: в Windows используются
установленные Edge/Chrome, на других системах — `npx playwright install chromium`; путь можно
задать через `CAPTURE_BROWSER`. Тесты проверяют запись 9:16 из трёх форматов камеры, звук,
движение, ориентацию, отсутствие текста суфлёра в кадрах, повторное открытие и сбой canvas.
Браузерная эмуляция размера телефона не заменяет проверку захвата на реальном iPhone/Safari.

## Ворота записи: тихий или пустой звук останавливает монтаж бесплатно (2026-09-07)

Дубль с телесуфлёра на iPhone пришёл с уровнем речи −57 дБ (камера телефона даёт −29 дБ),
после 32-й секунды — шум −73 дБ. Распознавание нашло 52 слова из 157 в сценарии, а конвейер
заметил это только в режиссёре монтажа — после исследования, медиатеки и визуальной
проверки ($1.19). Теперь `lib/speechGate.ts` останавливает такую запись до платных стадий:

- **Ворота 1 — уровень** (`measureRmsWindows` в `lib/ffmpeg.ts`, посекундный RMS, 90-й
  перцентиль): ниже −45 дБ (`SPEECH_MIN_LEVEL_DB`) — ошибка с цифрами, ничего не оплачено.
  Между −45 и −30 дБ — запись тихая, но живая: `audio_full.wav` для детектора тишины и
  распознавания усиливается до −25 дБ (итоговый рендер по-прежнему берёт звук из исходника
  и выравнивает loudnorm).
- **Ворота 2 — покрытие сценария** (после распознавания, до чистки речи, битов, медиатеки):
  меньше 10 слов или меньше 40 % слов сценария (`TRANSCRIPT_MIN_SCRIPT_RATIO`, при сценарии
  от 40 слов) — ошибка «распознано N слов из ~M (P %): речь слышна до X с из Y с».
  Расшифровка уже сохранена, повторный запуск того же файла её не оплачивает.
- `SPEECH_GATE=off` отключает обе проверки. Проверка режиссёра (`words.length < 10`) остаётся
  последней страховкой.

Телесуфлёр (`app/project/[id]/Teleprompter.tsx`): микрофон запрашивается с
`echoCancellation:false` — «обработка голоса» Safari на iPhone отдаёт микрофон на
25–30 дБ тише камеры, а подавлять эхо нечему (страница ничего не воспроизводит). В верхней
панели индикатор микрофона с пиковым уровнем за 4 с (зелёный выше −40 дБ, жёлтый до −60,
серый — тишина); во время записи через 3 с тихого звука появляется предупреждение, через
10 с полной тишины — подсказка «микрофон молчит». Запись не прерывается: длинные паузы
(ожидание текста) режет монтаж.

## Скорость монтажа: кадры медиатеки и потоки рендера (2026-09-07)

Разбор прогона «что такое блокчейн»: сборка медиатеки заняла 17 минут из ~25, рендер —
несколько минут. Внутри медиатеки на каждый проверочный кадр запускались два ffmpeg
подряд (кадр для модели, затем отдельный прогон под dHash), строго по очереди внутри
видео: 760 кадров — 1500 процессов. Что изменено, без влияния на стоимость и состав:

- `cutSegments` в `lib/storyAssetPack.ts`: один запуск ffmpeg на кадр с двумя выводами
  (jpg 384 px для модели и 9×8 серого для хэша, `hashFromGray` в `lib/sceneHash.ts`),
  `FRAME_PARALLEL` кадров одновременно (по умолчанию 4). Порядок кадров сохраняется по
  индексу окна, поэтому медиатека получается той же.
- Итоговый рендер: `-threads` по числу ядер минус два (4…12) вместо жёсткого 4;
  `RENDER_THREADS` задаёт явно. Пресет и CRF не менялись.
- Воркер пишет в журнал длительность каждой стадии (`⏱ стадия: N с → следующая`), чтобы
  следующий разбор скорости не требовал догадок.

Остальное время — сеть и модели: yt-dlp (42 разведки и 30 скачиваний по 3 параллельно),
запросы Brave, вызовы Claude/Haiku (чистка речи ~70 с, режиссёр, сопоставление). Их
параллельность не поднималась: YouTube ограничивает частоту, а порядок применения
результатов важен для повторяемости медиатеки.

## Обрыв кадров камеры в записи из браузера (2026-09-07)

Второй дубль с iPhone (с гарнитурой, звук −29 дБ) прошёл обе речевые проверки, а на
сверке готового ролика 47 точек из 51 оказались «кадр не снят»: видеодорожка `out.mp4`
длилась 8.7 с при звуке 73.5 с. В сырой записи Safari 255 кадров лежат в первых 8 с,
дальше 79 с только звук, при этом контейнер уверяет, что видео 87 с. Safari на iPhone
перестал вызывать `requestVideoFrameCallback`, холст перестал перерисовываться, и
`canvas.captureStream` не отдавал кадры. Прогон стоил $0.39 (режиссёр, сопоставление,
обложка). Изменено:

- `lib/portraitCapture.ts`: сторож кадров. Если rVFC молчит дольше двух интервалов,
  цикл рисования насовсем переводится на `requestAnimationFrame`; если застыл сам
  поток камеры (`currentTime` не растёт 3 с и кадров нет), захват останавливается с
  ошибкой, и телесуфлёр сохраняет записанную часть. `fps()` отдаёт кадры за секунду.
- Телесуфлёр показывает 🎥 к/с рядом с 🎤; ниже 10 к/с во время записи — предупреждение.
- `lib/ingestGate.ts` + `probe().videoDuration`: после нормализации записи из браузера
  видео короче звука больше чем на 2 с — стоп до платных стадий с цифрами.
- `selfCheck` результата сравнивает длительность видеодорожки со звуком: ролик с
  застывшим кадром больше не проходит под видом «73 с по контейнеру».

## Аудит надёжности записи и расходов, 2026-09-07 (восемь пунктов)

1. **Оборванное видео** — `lib/ingestGate.ts`: после нормализации видео короче звука больше
   чем на 2 с — стоп до платных стадий. Проверено на битом файле в работающем воркере.
2. **Сторож захвата** — `captureHealth` в `lib/portraitCapture.ts`: кадром камеры считается
   только новый кадр (rVFC или рост `currentTime`), перерисовка холста не в счёт. Молчание
   rVFC переводит цикл на `requestAnimationFrame`; 3 с без кадров — захват останавливается,
   дубль сохраняется. На телефоне запись идёт **с дорожки камеры напрямую**, минуя холст,
   если поток и так 9:16 (превью показывает тот же кадр); иначе — холст, как на компьютере.
   Что именно замолчало в Safari — rVFC, поток или захват холста — журналы не показывают.
3. **Обложка после проверок** — `renderPlan → selfCheck → сверка с планом → makeCover`.
4. **Режиссёрский план переиспользуется** — `director-plan.json` с ключом от исследования,
   блоков, медиатеки, слов, длительности, склеек, вкуса, модели и `DIRECTOR_PROMPT_VERSION`
   (поднимать при правке промпта). Сохраняется только план, прошедший проверку.
5. **Доставка отдельно от монтажа** — `lib/deliveryMarker.ts`: перед отправкой ролика
   воркер пишет `delivery-pending.json` (отпечаток исходника, хэш сценария, поля проекта);
   сетевое исключение при загрузке повторяется до 6 раз; повторный запуск с тем же
   исходником и сценарием только досылает готовый файл. Маркер снимается после `complete`.
6. **Исследование после проверок речи** — запускается после ворот распознавания и сразу
   сохраняется в проект; тексты ворот честно называют, что распознавание уже оплачено.
7. **Бюджет** — `reserveBudget/withBudget` в `lib/costLedger.ts`: оценка запроса держит
   место, пока провайдер не ответил (все вызовы Claude и зрения); проверка перед
   распознаванием; `MEDIA_PROJECT_MAX_COST_USD` (по умолчанию 6$, 0 — выключен) — предел
   на проект целиком с учётом прошлых прогонов из `cost-runs`. Brave и обложка идут
   последовательно и остаются на `assertBudget`.
8. **Кэш зрения** — `mergeAnalysisCache`: запись перечитывает актуальный файл, добавляет
   своё и пишет атомарно, записи по очереди; параллельные разборы больше не затирают друг
   друга. `ANALYSIS_CACHE_FILE` переопределяет путь (тесты).

держится при записи с дорожки, и запись с потока холста — для подтверждения виновника.

## Режим иллюстраций для объясняющих тем (2026-09-07)

В ролике «что такое блокчейн» 24 из 28 материалов были кадрами из YouTube-объяснялок:
поиск шёл «сначала видео», а веб-картинки искались только для блоков без видео (2 запроса
по 6 находок, принято 4), и провалы скачивания (403) не считались. Теперь для тем
EXPLAINER, HISTORY, PERSON, PRODUCT, OTHER (`imageLedTopic`, `MEDIA_IMAGE_LED=0/1`):

- иллюстрации первыми для каждого блока, видео только если картинки не нашлось;
- запросы про иллюстрации, схемы и фото вместо «official still poster»; 4 запроса по 10
  находок, но не больше `max_items_per_beat` принятых на блок (зрение платное);
- скачивание с заголовками браузера и ссылкой на источник, таймаут 15 с; провалы и
  мелкие картинки считаются (`imageFetchFailed`, `imageTooSmall`);

- говорящая голова из чужого видео отсеивается для любого блока (`noTalkingHeads`);
- режиссёр видит происхождение (ИЛЛЮСТРАЦИЯ / КАДР ВИДЕО) и правило 11: при равной
  оценке иллюстрация лучше кадра, один материал дважды не ставится.

`PACK_VERSION` 3 → 4: старые медиатеки пересобираются при следующем монтаже (платно).
`DIRECTOR_PROMPT_VERSION` 2: сохранённые режиссёрские планы не переиспользуются.

## Режиссёр: что ставить и когда (2026-09-07, «Одиссея» Нолана)

Разбор готового ролика: время карточек совпадало с речью, ошибки были в выборе.
Портрет Нолана под «билеты раскупили», картинка с «$250M» под «пять фактов», один кадр
на пять актёров и на пять стран, циклоп и сирены без картинок при их обилии в сети.

- **Перечисления** (`listItem` в блоках, `BEATS_VERSION` 2): три и больше имён, мест,
  существ подряд режутся на блоки по одному элементу со своей картинкой; уплотнение держит
  такой блок от `min_list_item_duration` (1.0 с), а не от 2.4 с; режиссёру они помечены
  «СПИСОК» — карточка на каждый элемент в порядке называния.
- **Честные потребности**: не просить инфографику бюджета или графику даты; для чисел —
  постер или кадр темы; для существ ещё не вышедшего фильма — классическая живопись.
- **Заголовок источника** (`sourceTitle`) виден сопоставлению и режиссёру: «Nolan's $250M
  Odyssey…» попадает к блоку про бюджет, портрет режиссёра узнаётся как Нолан.
- **Правила режиссёра 12–14** (`DIRECTOR_PROMPT_VERSION` 3): человек не раньше, чем назван;
  списки — по карточке на элемент; цифры и даты — постер или кадр с этой цифрой в заголовке.
- **Портретные картинки** (постер, портрет актёра) показываются целиком по высоте на
  размытой копии по бокам (`PORTRAIT_CARD_FILTER`), а не обрезаются до 16:9; порог размера
  для них по высоте.
- **Время**: блоки и медиатека собираются параллельно с чисткой речи (`prepareLibrary`,
  минус ~2 мин); сверка с планом проверяет вставки по `CONFORMANCE_PARALLEL` (4) сразу.

## Сценарий по свежим источникам, а не по памяти модели (2026-09-07)

Сценарий «Одиссеи» Нолана обещал премьеру и трейлер через полтора месяца после выхода
фильма: проект создавался маршрутом «сценарий по теме» из памяти модели, а путь
«исследование → сценарий по фактам» был выключен переменной окружения. Исследование,
собранное позже для монтажа, знало, что фильм вышел.

- Создание проекта и перегенерация сценария всегда начинаются с исследования по Brave
  (новости и веб) и пишут сценарий из его фактов (`generateScriptFromResearch`); пакет
  сохраняется в проект и второй раз для монтажа не оплачивается. Без источников — сценарий
  по памяти с явной пометкой `scriptNote` в ответе. `STORY_RESEARCH_SCRIPT=off` возвращает
  старую схему.
- В каждый запрос (исследование, сценарий, описание) передаётся сегодняшняя дата
  (`todayLine`); исследование отдаёт `status` (RELEASED / UPCOMING / ONGOING / PAST / UNKNOWN)
  и `statusNote` с датой, сценарист получает их строкой (`statusLine`) и правило: о вышедшем
  писать в прошедшем времени, не обещать премьер, которые уже были.

## Журнал расходов без дублей, отклонённая обложка видна (2026-09-07)

- **Дубли в журнале.** Копия леджера в `cost-runs` называлась по «сейчас», а `pipeline-cost.json`
  хранил своё время создания; разница в миллисекунды делала их разными прогонами, и итоги дня
  удваивались. Копия теперь именуется по времени создания леджера, а `appendSpendRuns`
  считает один прогон по проекту, статусу, сумме и времени (±15 с) и при записи чистит старые
  дубли (`dedupeSpendRuns`).
- **Обложка.** Отклонённая проверкой обложка всё равно собирается в `cover.jpg`, статус и
  причина (`coverStatus: failed`, `coverReason`) уходят с воркера на сайт; страница показывает
  её с причиной и кнопками «Перегенерировать обложку» и «Изменить заголовок». Одна платная
  генерация на нажатие, как и раньше; при повторном монтаже отклонённая остаётся отклонённой.
  Ручная перегенерация не подменяет принятую обложку отклонённой.
- **Промпт обложки.** Сюжетный объект не должен быть носителем текста (вывеска, табличка,
  экран, постер, билет с печатью): «SOLD OUT» на табличке уже провалил обложку. В промпт
  генератора добавлено: такой объект рисовать без единой читаемой буквы.

## Обложка: мелкий текст на фоне допустим, если осмыслен (2026-09-07)

Проверка отклонила обложку за буквы на вывесках кинотеатра позади лица («OOR REATTLET»):
на превью их почти не видно. Теперь vision-модель отдельно отдаёт `backgroundText`
(мелкие, далёкие, размытые надписи на вывесках и экранах) с признаком `sensible`. Такие
надписи не отклоняют обложку: осмысленные слова — норма, набор букв — замечание в журнале
(`warnings`), а не отказ. Заметный лишний текст (`extraText`: крупный, в фокусе, на переднем
плане) отклоняется как раньше. Промпт генератора разрешает на далёких вывесках несколько
настоящих слов на языке места (CINEMA, TICKETS, IMAX), запрещает выдуманные буквы.

## Сценарий от лица автора, а не пересказ статей (2026-09-07)

Сценарий «Какая криптовалюта даст 1000x» вышел сводкой выдачи: «сообщает Bloomberg», «Bitget
выпустил материал», «CryptoNews собрал список». Промпт требовал «писать только по фактам» и
молчал о голосе автора. Теперь оба промпта сценария пишут от первого лица: позиция и оценки
автора, 2–4 факта из исследования своими словами как опора, без названий изданий и списков
статей, даты и длинные числа только когда они и есть суть. В Настройках поле «Голос автора»
(`authorStyle`): кто он, о чём канал, тон, обороты, запреты — строка `authorLine` уходит в
каждый запрос сценария.

## Откат: сценарий пишет прежний сценарист, исследование даёт только дату и справку (2026-09-07)

Сценарий «по фактам исследования» вышел пересказом выдачи, а прежние сценарии по теме были
хорошими. Возвращён прежний промпт `SCRIPT_SYSTEM` с одним правилом: писать по состоянию на
сегодня, о вышедшем — в прошедшем времени, справку не пересказывать и источники не называть.
Исследование по-прежнему собирается до сценария (дата, статус, факты, и оно нужно монтажу),
но в промпт идёт `todayLine` и `todayBrief` — статус и до шести фактов без ссылок как фон.
Поле «Голос автора» убрано; `generateScriptFromResearch` в маршрутах не используется.

## Загрузка записи с телефона: повторы, докачка, экран не гаснет (2026-09-07)

Запись с iPhone оборвалась на 80 МБ из ~120: в журнале сайта `ECONNRESET` — экран погас
или Safari ушёл в фон, соединение разорвалось, клиент не повторял запрос. Теперь: сетевое
исключение повторяет тот же кусок до 6 раз с паузой (сервер отличает дубль от продолжения по
`x-offset`), HTTP-ошибки до 5 раз; файл и место обрыва остаются в памяти страницы, после
ошибки кнопка «Продолжить загрузку»; прогресс показывает мегабайты; на время загрузки и записи
запрашивается Screen Wake Lock, чтобы экран не гас.

Сценарий: правила понятности — каждый факт объяснён без контекста (какая схема, чьи утечки,
какие детали), тема — сам предмет, а не его трейлер; список объявлен в хуке; отсутствие даты в
справке не превращается в «даты нет». Исследование: отдельный запрос «дата выхода» и запрет
писать «не объявлено» из-за отсутствия в выдаче (GTA 6: 19 ноября 2026 в источниках была,
а модель писала «дата не объявлена»).
