# Codex для локального Gudini

Согласованный объём: сценарии и планы Veo через локальный Codex с подпиской ChatGPT, включая связанные стадии основного видео-конвейера. Исследование, текст, монтажные решения и проверки кадров используют общий транспорт. Карусели сохраняют отдельное подключение; Veo, генерация обложек, Brave и ASR остаются своими сервисами.

## Запуск

1. Установить Codex CLI и войти `codex login` через ChatGPT под Windows-пользователем сервера.
2. В `.env` задать `MEDIA_LLM_TRANSPORT=codex`, случайный `CODEX_BRIDGE_TOKEN` (минимум 32 символа). Старые ключи Claude можно оставить для ручного возврата.
3. На Windows выполнить `powershell -File deploy/start-codex-bridge.ps1`. Процесс скрыт, логи — `data/codex/bridge.*.log`.
4. `docker compose up -d --build gudini-site gudini-worker`. Контейнеры вызывают `http://host.docker.internal:43127`; порт не проксируется через Caddy. Все запросы к сервису, включая health, требуют bearer-ключ. Не открывать этот порт на роутере.

`deploy/start-codex-bridge.ps1 -InstallStartup` добавляет запуск при входе текущего пользователя Windows. Для отключения удалить ярлык `Gudini Codex` из папки автозагрузки Windows. До входа пользователя мост не работает.

При запуске без Docker переменная `CODEX_BRIDGE_URL` не нужна: сервер запускает CLI непосредственно. Для Docker ключ и настройки моделей должны совпадать с Windows-сервисом. После изменения `.env` перезапустить сервис и контейнеры. Если сервис уже работает, стартовый скрипт не запускает дубликат.

## Модели и контекст

- Сценарий: `CODEX_SCRIPT_MODEL=gpt-6-astra`.
- План и правка: `CODEX_STORY_MODEL=gpt-6-astra`.
- Остальные стадии: `CODEX_MODEL=gpt-6-astra`.
- Метаданные: `CODEX_UTIL_MODEL=gpt-5.6-luna`.
- Рассуждение: high, для метаданных medium. `CODEX_REASONING_EFFORT` явно переопределяет уровень для всех стадий.

Передаются действующие инструкции стадии, факты, профиль персонажа, тайминги и прикреплённые кадры. История диалога в приложении не передаётся. Встроенные инструкции программирования заменяются короткой ролью видео-ассистента; пользовательская конфигурация CLI не загружается. CLI работает в отдельной временной папке, без shell, веб-поиска, подагентов и приложений. Авторизация — только ChatGPT; API-ключи и идентификатор родительской задачи не наследуются.

Внешняя JSON Schema задаёт конверт `result: string`; внутри остаётся исходный текстовый или JSON-контракт стадии. Существующие парсеры и проверки плана проверяют содержимое. Отпечаток плана включает транспорт, модель, уровень рассуждения и версию адаптера. Старый план после переключения нужно пересобрать.

## Надёжность и расход

Сайт и воркер используют одну очередь Windows-сервиса. При прямом запуске без моста очередь отдельна для каждого серверного процесса. На CLI по умолчанию отводится 15 минут (`CODEX_TIMEOUT_MS`), ожидание очереди — до 30 минут. При ошибке входа, лимите или таймауте нет автоматического переключения на платный API и нет автоматического повтора всего запроса. Существующая ограниченная корректировка полученного плана сохраняется.

Каждая попытка сохраняет отдельный JSON в `data/codex/runs`: стадия, модель, уровень, время, статус, токены, идентификатор и хэш входа. API-цены из токенов не вычисляются. `$0` в отчёте означает отсутствие отдельного списания за API, а не отсутствие расхода подписки. Процент лимита из количества токенов не выводится.

Проверка конфигурации: `npx tsx scripts/check-codex.ts`. Реальный короткий вызов: добавить `--live`; он расходует подписку, но не вызывает Veo. Для теста зрения: `--live --vision <путь-к-красному-png>`.

Проверка полного планировщика без генерации видео: `npx tsx scripts/eval-planner-autonomy.ts --live --cases=explainer --output=data/codex-planner-smoke`.

Критерии приёмки: реальный текстовый и зрительный вызов через ChatGPT; доступ из рабочих контейнеров; отсутствие зависимости от ключа Anthropic; ошибки без платного перехода; журнал успешных и неудачных попыток; сохранение тестов режиссуры и генерации Veo.
