# Гудини (Gudini) — описание проекта

Контекст для ИИ-ассистента: что это за проект, из чего состоит и как используется.

## Что это

Гудини — веб-студия коротких вертикальных видео для стримеров. Полный цикл: стример вводит тему → ИИ пишет сценарий на ~60 секунд → стример читает его на камеру прямо на сайте (встроенный телесуфлёр с записью) → автомонтаж (9:16, субтитры по речи, перебивки, обложка, описание) → публикация в TikTok / YouTube Shorts / Instagram Reels в один клик.

Продакшен: https://gudini-production.up.railway.app (вход по паролю, страница /login; /terms и /privacy открыты).

## Архитектура

Два компонента, один репозиторий (github.com/paracetamolhaze/gudini, приватный):

1. **Сайт** — Next.js 15 (App Router, TypeScript), деплой на Railway из Dockerfile (node:22 + ffmpeg + fonts-liberation). Хранение: JSON-файлы на Railway Volume (`/app/data`): `db.json` (проекты), `settings.json` (ключи и OAuth-токены), `uploads/{id}/` (видео). Без СУБД.
2. **Воркер монтажа** — контейнер `gudini-worker` (docker-compose) на ПК владельца. Опрашивает сайт каждые 5 сек (`/api/worker/jobs`); когда стример жмёт «Смонтировать», сайт ставит задачу в очередь, воркер скачивает исходник, монтирует локально (мощный ПК + все ИИ-ключи из локального `.env`) и заливает результат обратно кусками по 4 МБ. Если воркер офлайн >90 сек — сайт монтирует сам на Railway в экономном режиме. Аутентификация воркера — Basic auth паролем сайта.

Важное ограничение хостинга: прокси Railway обрывает тела запросов ~10 МБ, поэтому ВСЕ загрузки видео (браузер→сайт и воркер→сайт) идут кусками по 4 МБ с ретраями и докачкой (заголовки x-offset / x-file-size, ответ 409 с фактическим размером при рассинхроне).

## Конвейер монтажа 2.0 — transcript-first, EDL (lib/pipeline.ts)

Принцип (вдохновлён video-use/AutoBroll/ReelMakerAI): ИИ рассуждает над транскрипцией со словными таймкодами и создаёт структурированный монтажный план (EditPlan); рендерер детерминированно исполняет его. ИИ не генерирует ffmpeg-команды. Флаг SMART_EDITING=false отключает планировщик (fallback — простой конвейер б-роллов).

1. Точная длительность по аудиодорожке (метаданным webm с камеры верить нельзя).
2. **Вырезка пауз**: края + длинные паузы внутри речи (>1.2 сек ужимаются до ~0.45); склейка сегментов в clean.mp4 с аудио-микрофейдами 15 мс на границах (без щелчков).
3. Распознавание речи на чистом таймлайне: ElevenLabs Scribe → Whisper → раскладка сценария (фолбэки).
4. Метаданные: заголовок/описание/хэштеги (Claude Sonnet).
5. **EditPlan** (lib/editPlanner.ts → lib/editPlan.ts): Claude-«режиссёр» получает тему + оригинальный сценарий + транскрипцию и возвращает события по индексам слов: A_ROLL (по умолчанию), B_ROLL (только для визуализируемого, число по содержанию 0–8, визуальные англ. запросы + альтернативы), PUNCH_IN (лёгкое приближение 1.04–1.08 на сильных фразах), TEXT_CALLOUT (крупный текст для цифр/цен/имён). Жёсткая валидация: клампы длительностей, запрет пересечений в дорожке, лимиты количества, неизвестное → отбрасывается. План сохраняется в uploads/{id}/edit-plan.json (задел под ручной timeline-редактор). Хук не закрывается б-роллом, лицо остаётся на эмоциях.
6. Материалы B_ROLL: свой broll{k}.mp4 → Runway (если ключ) → сток: несколько кандидатов с Pexels+Pixabay по primary+alt запросам, ранжирование (вертикальность, разрешение ~1080, длительность), дедупликация в ролике, кэш скачанного в data/broll-cache/.
7. Рендер по плану: base 1080×1920 cover-crop → punch-in (split+crop копии, overlay по интервалам) → б-ролл overlay (голос непрерывен) → субтитры → callouts. Аудио: loudnorm + опц. музыка с даккингом. libx264 veryfast.
8. **Субтитры фразовые**: 2–3 слова на экран (лимит символов, разрыв по паузам >0.6с и концам предложений), события НЕ пересекаются (не «прыгают» и не накладываются), белые, без знаков препинания; стиль настраиваем (CaptionStyle: maxWords, highlightKeyword, position, fontSize).
9. Обложка: кадр + заголовок → cover.jpg (TikTok cover_timestamp, IG thumb_offset, YouTube thumbnails.set).
10. **Self-check** результата: файл существует, длительность ±1.5с от ожидаемой, 1080×1920, звук есть — иначе ошибка.

## ИИ и ключи (Настройки сайта или .env)

| Ключ | Роль | Модель/API |
|---|---|---|
| ANTHROPIC_API_KEY | Сценарии (Opus 5), описания и план перебивок (Sonnet 5) | @anthropic-ai/sdk |
| ELEVENLABS_API_KEY | Субтитры по речи (Scribe, пословные таймкоды) | /v1/speech-to-text |
| OPENAI_API_KEY | Запасное распознавание (Whisper) | опционально |
| PEXELS_API_KEY / PIXABAY_API_KEY | Стоковые видео для перебивок | бесплатные |
| RUNWAY_API_KEY | ИИ-генерация перебивок (gen4_image → gen4_turbo), ~$0.30/клип | опционально |

Без ключей всё работает в демо-режиме (шаблонный сценарий, субтитры по тексту, без перебивок). Себестоимость ролика с ключами: ~5–7 центов (сценарий Opus ~3–4 ц. однократно, монтаж ~2 ц.).

## Публикация (lib/publish.ts)

- **YouTube Shorts**: OAuth Google (redirect /api/auth/youtube/callback), multipart-upload YouTube Data API v3. Подключён ✓. До аудита YouTube API видео принудительно приватные.
- **TikTok**: OAuth c PKCE (challenge = hex(sha256)), Content Posting API Direct Post, загрузка одним куском. Подключён через Sandbox ✓ (свои client key/secret, target users). До ревью посты приватные (авто-фолбэк SELF_ONLY). Для ревью нужно демо-видео.
- **Instagram Reels**: прямой Instagram Business Login (instagram.com/oauth/authorize, scopes instagram_business_basic + instagram_business_content_publish), токены graph.instagram.com, публикация контейнером REELS по публичному URL видео. Не доделан: заблокирован FB-аккаунт владельца (на проверке), осталось привязать IG-аккаунт и вписать Instagram App ID/Secret.
- Без подключённого аккаунта кнопка публикации работает в демо-режиме (симуляция).
- Аккаунты общие на сайт (один комплект). Мультипользовательности нет.

## Структура кода

- `app/` — страницы (главная-дашборд, project/[id] — степпер Сценарий→Съёмка(телесуфлёр+запись MediaRecorder)→Монтаж→Публикация, settings, login, terms, privacy) и API-маршруты (`app/api/...`).
- `lib/` — store.ts (JSON-хранилище, настройки), pipeline.ts (монтаж), ffmpeg.ts, transcribe.ts, subtitles.ts, broll.ts, ai.ts, publish.ts, origin.ts (адрес за прокси), workerState.ts (файл-отметка «воркер в сети»).
- `worker/index.ts` — воркер (tsx), использует те же lib/.
- `middleware.ts` — парольная защита (cookie после /login + Basic auth), публичные пути: /terms, /privacy, /login, отдача видео; отдача TikTok-верификации из env TIKTOK_VERIFY_CONTENT.
- `Dockerfile` (сайт, Railway), `Dockerfile.worker` + `docker-compose.yml` (воркер на ПК).
- `docs/SETUP-PLATFORMS.md` — как регистрировать приложения платформ.

## Что работает / что осталось

Работает: полный цикл на проде с воркером (запись → чанковая загрузка → монтаж на ПК с Scribe-субтитрами и стоковыми перебивками → публикация в YouTube и TikTok-песочницу).

Осталось: Instagram (после разблокировки FB), демо-видео и подача на ревью TikTok (выход из песочницы), аудит YouTube API (публичные видео), опц.: свой домен (DNS-верификация TikTok, обход проблем провайдерского DNS у up.railway.app), мультипользовательский режим, ручной выбор перебивок.
