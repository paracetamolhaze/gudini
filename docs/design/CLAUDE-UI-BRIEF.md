# Гудини: задание Claude Code на редизайн

Подготовлено 8 сентября 2026 по работающему интерфейсу и текущему коду. Запрос владельца: «красивый понятный дизайн, без глупых подсказок, с понятным интерфейсом». Это задание на реализацию, а не на очередной список рекомендаций.

## Результат

Преврати Гудини в аккуратную личную студию коротких видео. Пользователь открывает проект, сразу понимает его состояние и видит следующее действие. Красоту создают композиция, типографика, превью и хорошие отступы. Постоянные объяснения процесса, декоративные эмодзи и технические отчёты на основном экране должны исчезнуть.

Рабочий сценарий остаётся прежним: тема → сценарий → запись или загрузка → монтаж → просмотр и публикация. Два стиля монтажа сохраняются. Пользователь может вернуться к любой стадии и иметь две готовые версии одного проекта.

Сначала прочитай актуальный код и `git status`: репозиторий меняется параллельно. Сохранённые скриншоты показывают исходную точку; текущие типы, маршруты и обработчики определяют доступное поведение. Старые README и описания проекта местами уже не соответствуют реализации.

## Визуальное направление

Спокойная тёмная студия: тёплый графит, светлая типографика, один мягкий лавандовый акцент. Видео и обложки — главный визуальный материал. Не превращай рабочее приложение в рекламный лендинг или сложный ручной видеоредактор.

| Элемент | Решение |
|---|---|
| Фон | `#101114` |
| Основная поверхность | `#191A1F` |
| Поля / дополнительная поверхность | `#23252D` |
| Граница | `#343640`, тонкая, без свечения |
| Основной текст | `#F6F4EF` |
| Вторичный текст | `#B1B3BD`; мелкий текст остаётся читаемым |
| Акцент | `#C0B4FF`, текст на акцентной кнопке `#20183D` |
| Успех / внимание / ошибка | Отдельные сдержанные цвета + подпись или пиктограмма |
| Шрифт | Один системный стек с хорошей кириллицей: Segoe UI / system-ui / sans-serif |
| Размеры | Основной текст 16 px; вторичный 14 px; заголовок экрана 28–32 px; заголовок блока 18–20 px |
| Отступы | Шкала 4 / 8 / 12 / 16 / 24 / 32 / 48 px |
| Скругления | Поля и кнопки 10 px; панели 14–16 px |
| Кнопки | Высота от 44 px; одна акцентная, остальные вторичные или текстовые |
| Иконки | Один согласованный набор небольших контурных иконок; доступные названия у действий без текста |
| Анимация | Короткие переходы 120–180 ms; уважать reduced-motion |

Это стартовые токены, а не запрет на точную визуальную доводку. Проверяй контраст на настоящем экране. Убери градиенты с основных кнопок и логотипа, эмодзи перед каждым заголовком, постоянный рекламный слоган. Словесный знак «Гудини» может быть самодостаточным.

Глобальная навигация: компактная шапка «Гудини · Проекты · Расходы · Настройки», активный раздел виден. Отдельная постоянная боковая колонка ради трёх пунктов не нужна. Контент шириной до 1200 px, с аккуратными полями.

## Правила ясного интерфейса

1. У каждого состояния одно главное действие. Готовый ролик ведёт к просмотру или публикации; повторный монтаж становится вторичным действием.
2. Подсказка остаётся только если помогает принять решение, объясняет блокировку или предотвращает потерю данных. Не повторяй словами то, что уже объясняют заголовок, поле и кнопка.
3. Данные показываются на том шаге, где они нужны. Аккаунты публикации не должны занимать верх главной страницы. Имена моделей и устройство конвейера не нужны рядом с превью.
4. Важное не прячется: цена перед генерацией, выбранная версия видео, назначение публикации, ошибка и сохранность незагруженной записи.
5. Не создавай ложных обещаний: «за пару секунд», «бесплатно», «сам опубликует», «всё в порядке» без соответствующего состояния.
6. Русский интерфейс, спокойные короткие фразы. Глаголы в кнопках: «Сохранить», «Записать», «Смонтировать», «Скачать». Без оценок пользователя вроде «длинновато, сократи».
7. Ошибка загрузки списка не равна пустому списку. Недоступный баланс не равен нулю. Сохранённый план не равен готовому фильму. Результат другого стиля не делает выбранный стиль готовым.

## Экраны

### 1. Проекты

Вверху заголовок «Проекты» и компактный блок создания: поле «Тема видео», кнопка «Создать сценарий». Без вводного абзаца про весь продукт. У поля постоянная подпись; placeholder только приводит короткий пример темы.

Ниже — визуальный список проектов. В строке небольшое настоящее превью или нейтральный placeholder, название, дата, понятный статус и действие «Открыть»/«Продолжить». Превью берётся из уже доступной обложки или видео: новый платный запрос для миниатюры не нужен. Удаление — во вторичном меню, с сохранением защиты от случайного удаления. Расход проекта можно оставить небольшим вторичным значением.

Для пяти проектов не добавляй папки, теги, сортировки, вкладки и графики ради декоративной сложности. При загрузке — скелет списка. При ошибке — «Не удалось загрузить проекты» и «Повторить». Пустое состояние — «Проектов пока нет», без повторной формы создания.

Статусы: «Сценарий готов», «Запись загружена», «Монтируется», «Видео готово», «Нужна правка», «Опубликовано». Различай реальную публикацию, черновик, демонстрацию, пропуск и ошибку; не выводи успешный статус только по наличию записи в массиве `publications`.

### 2. Общая рамка проекта

Сверху: возврат к проектам, название проекта и компактный ряд этапов «Сценарий → Запись → Монтаж → Публикация». Технический ID не нужен в основном интерфейсе. Состояние этапа и текущий выбранный этап должны отличаться. Галочка означает реально выполненную работу.

На широком экране у монтажа и публикации две зоны: рабочие настройки слева, вертикальное превью выбранной версии справа (около 320–360 px). Видео сохраняет 9:16; оно не должно растягиваться или незаметно обрезаться CSS. Превью может оставаться в пределах видимой области при прокрутке.

На мобильном — одна колонка. На монтаже сначала заголовок и выбранный стиль, затем превью/состояние результата, настройки и действие. Этапы должны помещаться на 360 px без горизонтальной прокрутки всей страницы. Нижняя панель с главным действием допустима, если учитывает safe-area и не закрывает поля, ошибки и управление видео.

### 3. Сценарий

Основное место занимает текст, удобный для чтения и редактирования. Заголовок «Сценарий», рядом нейтральная оценка «258 слов · около 1 мин 43 с». Оценка явно приблизительная; не обещай точную минуту.

Главное действие: «Сохранить и продолжить». Вторичное: «Другой вариант». Покажи несохранённые изменения, сохранение и ошибку сохранения. Спиннер у генерации не должен появляться при обычном сохранении. Сохрани ручное редактирование и существующую генерацию; не добавляй новые AI-функции без рабочего API.

### 4. Запись

До появления файла — ясный выбор «Записать с телесуфлёром» и «Загрузить видео». Одна область загрузки; не повторяй её несколькими одинаково заметными кнопками. Советы о свете и звуке убери с постоянного экрана.

После появления файла — превью, длительность, статус загрузки и главное действие «К монтажу». «Заменить запись» становится вторичным. Сохранённая локальная запись показывается нейтральной карточкой: «Запись сохранена на устройстве» + «Продолжить загрузку» / «Скачать». Это не красная ошибка.

Во время записи и загрузки нельзя запускать конфликтующие операции. При сбое сети объясни результат: «Загрузка прервалась. Запись сохранена на устройстве» и дай рабочее продолжение.

Телесуфлёр — отдельный чувствительный экран. Меняй его оформление осторожно, не трогая механику камеры, звука, прокрутки, сегментной отправки, восстановления IndexedDB и скачивания записи. Не перемонтируй компонент камеры при косметическом переключении UI.

### 5. Монтаж

Стиль выбирается двумя небольшими визуальными карточками с понятным различием:

| Название в интерфейсе | Короткая подпись | Внутренний ID |
|---|---|---|
| С картинками | Иллюстрации над автором | `cards` |
| AI-фильм | Видеосцены Google Veo | `ai_film` |

В каждой карточке можно использовать лёгкую схему расположения автора и вставки. Это объясняет выбор лучше большого абзаца. Название «Карточки» допустимо оставить, если визуальное отличие уже совершенно ясно.

**С картинками:** до запуска главное действие «Смонтировать». Во время работы — текущий понятный этап и реальный прогресс; после — выбранное видео, короткий статус и «К публикации». Повторный монтаж вторичен. Если готова только другая версия, показать «Эта версия ещё не создана» и отдельное действие «Посмотреть AI-фильм», не ставить общую зелёную галочку.

**AI-фильм:** сохранить две отдельные фазы.

- Без плана: «Подготовить план». Небольшая подпись «Без генерации видео» допустима. Не называй весь шаг бесплатным: разбор истории может стоить денег.
- Готовый план: на виду длительность ролика, примерная цена генерации, приблизительное время и последовательность сцен. Кнопка «Создать видео · ≈ $…». Числа берутся из ответа API, не из макета.
- Режимы сцены по-русски: «Автор», «Сцена на весь экран», «Автор + сцена». Вместо широкой технической таблицы — компактный список: время, режим, одно описание кадра.
- `AUTHOR`, `FULL_AI`, `HYBRID`, Universe Lock, IDs, модели, reference hash, profiles, приоритеты, группы, цепочки и эффективность генерации — в закрытых по умолчанию «Технических сведениях». Значимые ограничения бюджета остаются рядом с действием.
- Не называй число API-вызовов числом сцен: эти величины могут различаться.
- Устаревший план: «Обновите план перед генерацией» и «Обновить план». Генерация заблокирована. При нуле сцен покажи понятную причину и обновление плана.
- После генерации: превью и переход к публикации. Фактические расходы последнего запуска отделены от оценки плана. Повтор может использовать готовые сцены; не обещай нулевую стоимость всем повторам заранее.

Во всех действиях версия одна и та же: выбранный стиль → его превью → его скачивание → его публикация. Сохрани оба `outputs`. Особо проверь старые проекты без `outputs`.

### 6. Обложка и публикация

Вначале выбранная версия и её превью, рядом обложка. Далее редактируемые заголовок, описание и хэштеги. Не повторяй хэштеги одновременно в поле и отдельной строке без причины.

Список платформ показывает название, аккаунт и состояние подключения. Неподключённая платформа предлагает «Подключить», а не выглядит готовой к реальной публикации. Основное действие должно ясно называть назначения или работать с явно выбранными платформами. Не делай три одинаково главные кнопки массовой и индивидуальной публикации.

Сохрани отдельные способы публикации и черновиков. TikTok требует собственной формы и выбора параметров; массовая кнопка не должна обходить этот шаг. Успех, приватная публикация, черновик, demo, skipped и error должны читаться по-разному. Частичная ошибка не превращается в полностью зелёное сообщение.

Для обложки: «Обложка», просмотр, «Изменить заголовок», «Создать заново». При проблеме покажи конкретную причину. Готовое видео и отклонённая обложка — разные состояния. Повторная генерация обложки остаётся отдельным платным действием.

### 7. Настройки и расходы

Настройки сгруппируй в «Аккаунты», «Оформление», «Сервисы». Сначала доступные пользователю действия, потом закрытые технические параметры. Кнопка подключения находится у своей платформы. Активный аккаунт явно отмечен, переключение нескольких аккаунтов сохраняется.

Убери из обычного вида пути файлов, переменные окружения, OAuth-инструкции и длинные объяснения реализации. Технические поля можно раскрыть отдельно. Не добавляй неподдерживаемые настройки Google. Перед переименованием полей проверь backend: часть текущих текстов про Runway, запасную обложку из видео и шрифты устарела.

Раздел «Балансы» можно назвать «Расходы», сохранив маршрут `/balances`. На виду — расходы и доступные остатки сервисов, ниже история. Ручная оценка отличается от ответа сервиса; отсутствие данных обозначается «Недоступно». Оставь знак приблизительности и дату проверки. Никаких сообщений «всё в порядке», если данные не получены.

## Код и ограничения реализации

Основные файлы:

- `app/layout.tsx`, `app/globals.css` — общая рамка и токены.
- `app/page.tsx` — проекты.
- `app/project/[id]/page.tsx` — сценарий, запись, монтаж, обложка, публикация.
- `app/project/[id]/Teleprompter.tsx` — чувствительная механика записи.
- `app/settings/page.tsx`, `app/balances/page.tsx` — настройки и расходы.
- `lib/store.ts` — реальные типы состояния, два `outputs`.
- `lib/montageStyle.ts`, `lib/aiFilm/types.ts` и маршруты проекта — контракты, которые UI должен правильно отображать.

Собери небольшой набор переиспользуемых компонентов: Button, Field, StatusBadge, ProjectSteps, StylePicker, VideoPreview, EmptyState, ErrorState. Выноси их по мере необходимости; не переписывай весь продукт ради архитектуры. Не добавляй библиотеку UI целиком только ради пары компонентов. Изолируй стили страниц; изменение `.btn`, `video` и общих селекторов не должно ломать телесуфлёр и формы публикации.

Не меняй алгоритмы монтажа, промпты Veo, провайдеров, расценки, бюджеты, кэш, форматы файлов и API без конкретной необходимости для заявленного UI-поведения. Не запускай платную генерацию, новую запись или реальную публикацию при визуальной проверке. Не удаляй проекты и существующие результаты. Для тестов состояний используй изолированные фикстуры, а не изменения базы пользователя.

Связанные дефекты, которые нужно проверить в новом интерфейсе: ошибка загрузки проектов сейчас маскируется пустым списком; общий `processedVideo` может давать «Готово» для другого выбранного стиля; ссылка скачивания на публикации должна учитывать `pubStyle`. Исправляй соответствующее UI-поведение, сохраняя действующие API.

## Порядок работы и приёмка

1. Сними текущие экраны, прочитай обработчики, зафиксируй состояния. Посмотри приложенные материалы. Сформулируй выбранную композицию в нескольких предложениях и переходи к реализации.
2. Внедри токены, шапку, кнопки, формы и статусы. Приведи главную к новому виду.
3. Оформи сценарий и запись, затем оба варианта монтажа и публикацию. Заверши настройки и расходы.
4. Проверь реальные страницы в браузере на ширинах 1440, 1024, 390 и 360 px. Сделай скриншоты, исправь найденные переполнения, отступы и слабую иерархию. Не ограничивайся успешной компиляцией.
5. Запусти `npm run typecheck`, `npm test`, `npm run build`. При изменениях записи/телесуфлёра или общих стилей, влияющих на него, также `npm run test:capture`.
6. В результате покажи обновлённые экраны, перечень изменений и результаты проверок. Если часть состояния не удалось воспроизвести, назови её прямо. Сам факт наличия красивого макета не означает завершение реализации.

Готово, когда:

- На каждом шаге за несколько секунд понятно, где пользователь, что уже готово и что делать дальше.
- На основном экране нет длинных инструкций, декоративных эмодзи, сырых ошибок и терминов конвейера.
- Главное действие одно; восстановление после ошибки доступно рядом с ошибкой.
- Цена Veo видна до платной генерации. Подготовка плана не выдаётся за полностью бесплатную.
- Переключение стилей сохраняет оба результата. Превью, скачивание и публикация используют выбранную версию, включая старые проекты.
- Проверены: пустой проект, сохранённый сценарий, несохранённый текст, запись на устройстве, загрузка/сбой сети, монтаж, ошибка, устаревший и пустой AI-план, готовность только другой версии, готовый ролик с проблемной обложкой, частичная публикация, недоступный баланс.
- Поля имеют видимые связанные подписи; у иконок есть доступные имена; работают Tab/Enter/Escape и заметный focus. Статус понятен без цвета.
- На мобильном нет горизонтального скролла страницы, перекрытых кнопок и обрезанного превью. Поля не вызывают нежелательный zoom iPhone; safe-area сохранена.
- UI не добавляет новых платных вызовов при открытии страницы, переключении вкладок или показе миниатюры.
