# Автономный планировщик: реализация и проверка

Статус на 14 сентября: после пополнения лимита проверка продолжена. Четыре тестовых сценария проходят ворота, конечные постановки просмотрены. Для новости и истории проверены новые автоматические корректировки сохранённых первых ответов; это не четыре новых независимых прогона финальной версии. Рабочая версия установлена на сайт и воркер через Docker Compose. Сайт отвечает HTTP 200, воркер запущен, хэши трёх основных файлов в контейнере совпадают с локальными. Перед перезапуском активных задач не было. Все результаты ниже сохранены, включая неудачные.

## Общий путь, а не ручная правка тестового фильма

- `directorPrompt.ts` задаёт одну режиссёрскую процедуру для первого ответа и корректировки: смысл, статус утверждения, задачи истории, участники, выполнимое действие, видимое доказательство, камера, монтажное время. Убраны накопленные конкурирующие инструкции и требование заполнять ролик произвольным числом сцен.
- Первый ответ получает схему полного плана, корректировка — только схему изменений. В обоих вызовах передаётся тот же полный список фактов, который использует проверка, а также бюджет. Раньше `researchFacts` до модели не доходил.
- Второй вызов получает первый план, конкретные замечания и допустимые адреса изменений. Незатронутые решения сохраняет существующий механизм ограниченной корректировки.
- Не более двух вызовов на план. Некорректный JSON первого ответа может использовать второй вызов для восстановления структуры; третьего творческого вызова после него нет. Ошибки транспорта, авторизации и бюджета не маскируются под ошибки JSON.
- Если корректировка не удалась, первый кандидат сохраняется вместе с запретами. Пустой JSON без битов больше не превращается в «успешный» авторский план. Допущенный кандидат выигрывает у заблокированного.
- Производственный путь сохраняет вход, все сырые ответы и промпты, обоих кандидатов, выбор и журнал применённых/отклонённых изменений в отдельную папку каждого запуска `ai-film/story-calls/<run-id>`.

## Исправления, воспроизведённые тестами

Полный набор: 583 из 583 тестов. `tsc --noEmit` и `git diff --check` проходят. Добавлено одиннадцать тестов автономного пути; ошибки структуры, передачи фактов, отказа корректировки, адреса предмета и проверки состояния сначала воспроизведены падающими тестами.

Замечание с адресом предмета `B4/envelope` теперь открывает сцену `B4` для корректировки. Проверка присутствия учитывает `scene.who`, действие и движение, а неоднозначность передаётся во второй вызов. Проверка исходного состояния не соединяет независимые предложения о разных людях в выдуманное завершение передачи: «конверт у женщины; рука курьера пуста» не означает «конверт у курьера».

## Живой эксперимент

Четыре коротких синтетических сценария, по 36 секунд расчётной речи: учебная новость, историческая реконструкция, условная притча, объяснение выключателя. Это проверка переноса на разные задачи, не фактчекинг реальных новостей и не тест видео. Входы не подгонялись по полученным планам, ответы руками не редактировались.

Стоимость: $0.541906 по учёту провайдера. Veo и изображения не вызывались. В первом пакете предел ответа был 10000 токенов, в производственном пути 16000; поэтому это не точное воспроизведение всех производственных настроек. В повторной проверке предел выровнен до 16000, но провайдер отклонил оба запроса до ответа модели. Дополнительных расходов в журнале нет.

Бесплатное воспроизведение после исправлений убрало ложный запрет передачи конверта. Настоящие проблемы костюма и события без перехода остались. Прохождение ворот у двух сценариев не доказывает качество всех решений. Промпт назначения участников уточнён после первого пакета; новая версия ещё не проверена живым ответом из-за лимита ключа.

Артефакты: `data/planner-autonomy` — первый пакет и бесплатное воспроизведение; `data/planner-autonomy-run2` — отклонённые попытки проверки. Полные планы и конечные запросы содержатся в `result.json` / `replay.json`.

## Повторяемая проверка

`npm run eval:planner` бесплатно воспроизводит сохранённые ответы. Возвращает ненулевой код, если есть запрет или ошибка; не выдаёт блокированный результат за успешную проверку.

Живой режим включается только флагом `--live`. Поддерживаются `--cases=history,philosophy`, `--output=data/<новая-папка>` и `--limit=0.45`. Ограничение расходов жёсткое. Сохранять новый эксперимент нужно в отдельную папку, чтобы не перезаписать контрольные ответы.

## Завершение после пополнения лимита

Новые расходы составили $0.554978 из разрешённого $1. Veo и изображения не запускались. Вызовы используют производственный предел 16000 токенов. Сначала выполнены четыре плана с одной штатной корректировкой; затем для двух найденных сбоев повторены только корректировки исходных ответов. Сами планы и запросы руками не правились.

Последние общие исправления:

- Переназначение роли открывает все появления героя, а не только сцену с замечанием. Если изменение `playedByGudini` не охватило остальные появления, корректировка отклоняется целиком. Это устраняет ситуацию, когда письмо получает отдельный курьер, а уходит с ним Гудини.
- Удаление события или задачи принимает как строку идентификатора, так и объект `{id}`. Модель пыталась удалить лишний пункт контракта, но прежний обработчик искал событие `[object Object]`.
- Пустота исключена из признаков физического повреждения. «Портфель на пустой скамье» больше не означает повреждённый портфель. Проверки разрыва и разрушения сохранены.

| Новость | 4 сцены, нет запретов | Посетитель оставляет портфель, сотрудница поднимает, посетитель возвращается, получает портфель. Один и тот же назначенный участник, неизвестный способ установления личности не выдуман. |
| История | 4 сцены, нет запретов | Лист складывают, запечатывают, передают курьеру, курьер уносит. Курьер отдельный участник в обеих сценах. |
| Притча | 3 сцены, нет запретов | Взгляд в знакомую комнату, остановленная рука, переход в сад. Первый кандидат сохранён, ненужная корректировка не принята. |

Оставшиеся предупреждения не скрыты: плотность действий и обстановка у истории, длинный авторский хвост у новости/притчи, неподтверждённый статус условного примера у объяснения. Этот небольшой набор подтверждает работу проверенного пути, но не гарантирует отсутствие ошибок на любом будущем сценарии и не измеряет выполнение Veo.

Артефакты последней проверки: `data/planner-autonomy-run3`, `data/planner-autonomy-run3b`, `data/planner-autonomy-final-history`, `data/planner-autonomy-final-news`. Последние две папки используют первый ответ из соответствующего предыдущего запуска (`reusedFirst: true`) и один новый платный вызов корректировки. `npm run eval:planner -- --output=<папка> --cases=<тема>` воспроизводит такой запуск бесплатно.
