# Гудини (Gudini) — описание проекта

Контекст для ИИ-ассистента: что это за проект, из чего состоит и как используется.

## Что это

Гудини — веб-студия коротких вертикальных видео для стримеров. Полный цикл: стример вводит тему → ИИ пишет сценарий на ~60 секунд → стример читает его на камеру прямо на сайте (встроенный телесуфлёр с записью) → автомонтаж (9:16, субтитры по речи, перебивки, обложка, описание) → публикация в TikTok / YouTube Shorts / Instagram Reels в один клик.

Продакшен: https://gudini-production.up.railway.app (вход по паролю, страница /login; /terms и /privacy открыты).

## Архитектура

Два компонента, один репозиторий (github.com/paracetamolhaze/gudini, приватный):

1. **Сайт** — Next.js 15 (App Router, TypeScript), деплой на Railway из Dockerfile (node:22 + ffmpeg + fonts-liberation). Хранение: JSON-файлы на Railway Volume (`/app/data`): `db.json` (проекты), `settings.json` (ключи и OAuth-токены), `uploads/{id}/` (видео). Без СУБД.
2. **Воркер монтажа** — контейнер `gudini-worker` (docker-compose) на ПК владельца. Опрашивает сайт каждые 5 сек (`/api/worker/jobs`); когда стример жмёт «Смонтировать», сайт ставит задачу в очередь, воркер скачивает исходник, монтирует локально (мощный ПК + все ИИ-ключи из локального `.env`) и заливает результат обратно кусками по 4 МБ. Если воркер офлайн >90 сек — сайт монтирует сам на Railway в экономном режиме. Аутентификация воркера — Basic auth паролем сайта.

Важное ограничение хостинга: прокси Railway обрывает тела запросов ~10 МБ, поэтому ВСЕ загрузки видео (браузер→сайт и воркер→сайт) идут кусками по 4 МБ с ретраями и докачкой (заголовки x-offset / x-file-size, ответ 409 с фактическим размером при рассинхроне).

## Конвейер монтажа 2.0 — transcript-first, EDL (lib/pipeline.ts)

Принцип (вдохновлён video-use/AutoBroll/ReelMakerAI): ИИ рассуждает над транскрипцией со словными таймкодами и создаёт структурированный монтажный план (EditPlan); рендерер детерминированно исполняет его. ИИ не генерирует ffmpeg-команды. Флаг SMART_EDITING=false отключает планировщик (fallback — простой конвейер б-роллов).

1. Точная длительность по аудиодорожке (метаданным webm с камеры верить нельзя).
2. Распознавание речи ДО вырезки, на полном таймлайне: ElevenLabs Scribe → Whisper → раскладка сценария (фолбэки).
3. **Speech Cleanup 2.1** (lib/speechCleanupPlanner.ts → lib/speechCleanupPlan.ts, флаг SMART_SPEECH_CLEANUP): Claude-монтажёр сверяет транскрипцию с оригинальным сценарием и планирует чистку — REMOVE_FRAGMENT (запинки «эээ/эмм», слова-паразиты не из сценария, повторы «я я», фальстарты, самоисправления) и SHORTEN_PAUSE с семантикой (INTENTIONAL — оставить, UNNECESSARY — ужать до 0.45с). Жёсткая валидация: confidence ≥0.7, фрагмент ≤4с/≤12 слов, суммарно ≤min(15%, 12с), хук (<2с) не трогается, границы по стыкам слов с запасом 40–50мс; сомнение = не резать. План сохраняется в speech-cleanup-plan.json. Каты исполняются детерминированно (склейка сегментов в clean.mp4, аудио-микрофейды 15мс на каждой границе), таймкоды слов пересчитываются (remapWords) — вырезанное выпадает и из субтитров. Фолбэк при любом сбое ИИ: механические паузы (>1.2с → 0.45с), продакшен не падает. Тесты: tests/*.test.ts (29 шт, `npm test`, node:test+tsx): валидация EditPlan/чистки, пересечения, группировка субтитров, тишина, фолбэки.
4. Метаданные: заголовок/описание/хэштеги (Claude Sonnet).
5. **EditPlan** (lib/editPlanner.ts → lib/editPlan.ts): Claude-«режиссёр» получает тему + оригинальный сценарий + транскрипцию и возвращает события по индексам слов: A_ROLL (по умолчанию), B_ROLL (только для визуализируемого, число по содержанию 0–8, визуальные англ. запросы + альтернативы), PUNCH_IN (лёгкое приближение 1.04–1.08 на сильных фразах), TEXT_CALLOUT (крупный текст для цифр/цен/имён). Жёсткая валидация: клампы длительностей, запрет пересечений в дорожке, лимиты количества, неизвестное → отбрасывается. План сохраняется в uploads/{id}/edit-plan.json (задел под ручной timeline-редактор). Хук не закрывается б-роллом, лицо остаётся на эмоциях.
6. Материалы B_ROLL (2.2, semantic): свой broll{k}.mp4 → **сток с vision-отбором** → Runway-генерация как последний фолбэк (BROLL_SOURCE=runway меняет приоритет). Планировщик даёт visualIntent (subject/action/environment/mustHave/avoid); кандидаты Pexels+Pixabay → технический преранк → TOP-3..5 → vision-анализ ПРЕВЬЮ-тумбнейла (1 раз на ассет, кэш data/broll-cache/analysis.json) → детерминированный матчинг: final = 0.7·relevance + 0.3·tech, hard reject по avoid/mustHave (все отклонены → событие в A-roll → Runway-спасение). Трейс решений — uploads/{id}/broll-trace.json. Vision-сбой → технический фолбэк. Highlight в субтитрах — только по captionHighlights из плана (цифры/имена/панч-слова), большинство фраз белые. Панч-ины: ≤~5/мин и зазор ≥5с. Self-check расширен: fps≈30, аудио≈видео, blackdetect у монтажных точек.
7. Рендер по плану: base 1080×1920 cover-crop → punch-in (split+crop копии, overlay по интервалам) → б-ролл overlay (голос непрерывен) → субтитры → callouts. Аудио: loudnorm + опц. музыка с даккингом. libx264 veryfast.
8. **Субтитры фразовые**: 2–3 слова на экран (лимит символов, разрыв по паузам >0.6с и концам предложений), события НЕ пересекаются (не «прыгают» и не накладываются), белые, без знаков препинания; стиль настраиваем (CaptionStyle: maxWords, highlightKeyword, position, fontSize).
9. Обложка (lib/cover.ts): **ИИ-key-art с нуля** — стример один раз загружает reference-фото лица (data/face.jpg, Настройки); для каждого ролика Claude-арт-директор анализирует сценарий и выдаёт концепт (headline 2–5 слов, эмоция, сюжетный фон, image_prompt) → Runway gen4_image строит вертикальный кадр с identity-reference (@streamer, сходство сохраняется, эмоция/поза/фон новые, нижняя треть чистая, без текста) → текст наносит наш рендерер (ASS: headline белая+жёлтая строки, subheadline) — кириллица всегда читаема. Концепт сохраняется в cover-concept.json. Без фото/ключа Runway или при сбое — фолбэк: кадр из видео + заголовок. Воркер подтягивает фото с сайта перед монтажом. Обложка передаётся платформам (TikTok cover_timestamp, IG thumb_offset, YouTube thumbnails.set).
10. **Self-check** результата: файл существует, длительность ±1.5с от ожидаемой, 1080×1920, звук есть — иначе ошибка.

## Обложки — только Full-AI (lib/coverPipeline.ts)

Единственный режим: image-модель рисует обложку целиком (лицо + сцена + типографика).
Фолбэков нет вообще — ни детерминированного рендерера, ни Runway, ни кадра из видео, ни другой модели.

**Железное правило: одно действие пользователя = максимум одна платная генерация.**
QC никогда не запускает генерацию сам — автоматических повторов в системе нет.

```
Сценарий → Claude: 3 варианта headline + смысловые якоря
  → semantic + form preflight (бесплатно, до 2 текстовых попыток)
       якорь не удержан ни разу → HEADLINE_FAILED (картинка не заказывалась)
       якорь удержан → ОДИН выбранный headline
  → ОДНА генерация Gemini Flash → QC
       PASS → cover.jpg
       FAIL → COVER_FAILED: обложки нет, в интерфейсе кнопки
              «Перегенерировать» и «Изменить заголовок».
              Только нажатие пользователя создаёт новый запрос и новую оплату.
```

- **Провайдер** `FULL_AI_COVER_MODEL=google/gemini-3.1-flash-image` — выбран по бенчмарку (6/6 точных
  кириллических заголовков против двух дефектов у Pro, вдвое дешевле). Pro автоматически не используется.
- **`FULL_AI_COVER=false`** — обложки просто не генерируются; это выключатель, а не переключение
  на другой способ.
- **Headline решает всё** (его рисует сама модель): максимум 5 слов, идеально 2–4, до 3 строк, без
  стрелок/процентов/длинных чисел. «ТИГР / ВО ДВОРЕ / НЕ БЕГИ» → «ТИГР / У ДОМА»; «5000$ / СТАЛИ /
  300$» → «ДЕНЬГИ / СГОРЕЛИ». Kicker по умолчанию отсутствует (лишний текст = риск брака).
- **QC Gate** (`lib/coverQc.ts`): vision-проверка (Haiku 4.5, ~$0.002) — нормализованное сравнение
  headline, лишний читаемый текст (реальный дефект: «ТОЛШИЙ ШИНСВ» поверх верного заголовка),
  читаемость, узнаваемость лица, анатомия, критические артефакты. Кикер между строками заголовка —
  валидная вёрстка. Недоступность QC — это FAIL, а не пропуск проверки.
- **Headline Preflight** (`lib/coverHeadline.ts`) — обязательный ШЛЮЗ перед платной генерацией.
  Claude даёт 3 коротких варианта и 1–3 смысловых якоря (`headlineAnchor`, например `["тигр"]`),
  победителя выбирает детерминированный код. Смысл важнее формы: вариант, потерявший предмет ролика
  («НЕ БЕГИ» вместо «ТИГР ВО ДВОРЕ»), не побеждает никогда, даже с идеальной формой. Дальше — баллы
  формы (слова, буквы, спецсимволы, цифры, пунктуация, служебные слова), затем информативность,
  затем краткость. Логи — `cover-headline-preflight[-N].json`.
  **Если якорь потеряли все три варианта, картинка НЕ заказывается**: система бесплатно просит новые
  варианты с жёстким требованием якоря (максимум 2 текстовые попытки). Не помогло — `HEADLINE_FAILED`
  и кнопка «Сгенерировать заголовок заново»; денег при этом не потрачено. Явный заголовок
  пользователя проходит шлюз без проверки якоря — это его осознанный выбор.
- **`cover.jpg` создаётся исключительно после QC PASS.**
- Ручная перегенерация — `POST /api/projects/[id]/cover`, необязательное тело `{headline}` позволяет
  пользователю задать свой короткий заголовок. Один запрос = одна генерация.
- Артефакты: `cover-concept.json`, `cover-prompt.txt`, `cover-attempt-1.png`, `cover-qc-1.json`,
  `cover-final.png`, `cover.jpg`, `cover-mode.json` (в нём `generations: 1`, `automaticRetries: 0`).
  Статистика — `data/cover-stats.json`: generated / passedQc / failedQc / manualRegenerations + типы дефектов.
- Цена (замерено): любой исход одного запуска ~$0.070 (генерация $0.068 + QC $0.002).
- `lib/coverTypography.ts` и `lib/coverLayout.ts` оставлены в репозитории для истории/rollback,
  но production-путь в них не заходит.

Без ключей всё работает в демо-режиме (шаблонный сценарий, субтитры по тексту, без перебивок). Себестоимость ролика с ключами: ~5–7 центов (сценарий Opus ~3–4 ц. однократно, монтаж ~2 ц.).

## Публикация (lib/publish.ts)

- **YouTube Shorts**: OAuth Google (redirect /api/auth/youtube/callback), multipart-upload YouTube Data API v3. Подключён ✓. До аудита YouTube API видео принудительно приватные.
- **TikTok**: OAuth c PKCE (challenge = hex(sha256)), Content Posting API Direct Post, загрузка одним куском. Подключён через Sandbox ✓ (свои client key/secret, target users). До ревью посты приватные (авто-фолбэк SELF_ONLY). Для ревью нужно демо-видео.
- **Instagram Reels**: прямой Instagram Business Login (instagram.com/oauth/authorize, scopes instagram_business_basic + instagram_business_content_publish), токены graph.instagram.com, публикация контейнером REELS по публичному URL видео. Не доделан: заблокирован FB-аккаунт владельца (на проверке), осталось привязать IG-аккаунт и вписать Instagram App ID/Secret.
- Без подключённого аккаунта кнопка публикации работает в демо-режиме (симуляция).
- Аккаунты общие на сайт (один комплект). Мультипользовательности нет.

## Структура кода

- `app/` — страницы (главная-дашборд, project/[id] — степпер Сценарий→Съёмка(телесуфлёр+запись MediaRecorder)→Монтаж→Публикация, settings, login, terms, privacy) и API-маршруты (`app/api/...`).
- `lib/` — store.ts (JSON-хранилище, настройки), pipeline.ts (монтаж), ffmpeg.ts, transcribe.ts, subtitles.ts, broll.ts, ai.ts, publish.ts, origin.ts (адрес за прокси), workerState.ts (файл-отметка «воркер в сети»), обложки: coverPipeline.ts (гибрид), coverTypography.ts (селектор), coverQc.ts (QC-гейт), coverProvider.ts (Gemini Flash + ffmpeg-финиш), coverPrompt.ts, coverLayout.ts, coverStats.ts.
- `worker/index.ts` — воркер (tsx), использует те же lib/.
- `middleware.ts` — парольная защита (cookie после /login + Basic auth), публичные пути: /terms, /privacy, /login, отдача видео; отдача TikTok-верификации из env TIKTOK_VERIFY_CONTENT.
- `Dockerfile` (сайт, Railway), `Dockerfile.worker` + `docker-compose.yml` (воркер на ПК).
- `docs/SETUP-PLATFORMS.md` — как регистрировать приложения платформ.

## Что работает / что осталось

Работает: полный цикл на проде с воркером (запись → чанковая загрузка → монтаж на ПК с Scribe-субтитрами и стоковыми перебивками → публикация в YouTube и TikTok-песочницу).

Осталось: Instagram (после разблокировки FB), демо-видео и подача на ревью TikTok (выход из песочницы), аудит YouTube API (публичные видео), опц.: свой домен (DNS-верификация TikTok, обход проблем провайдерского DNS у up.railway.app), мультипользовательский режим, ручной выбор перебивок.
